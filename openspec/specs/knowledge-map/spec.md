# knowledge-map Specification

## Purpose

给题目一套共享的两层知识点词典：学科大点与具体点、每个点的别名、题目与知识点的多对多关联，以及把重复叫法合并到一处的规则。弱项统计沿这些关联汇总。

## Requirements

### Requirement: 知识点只有两层
知识点树 MUST 最多两层：根节点的上级为空，子节点的上级 MUST 是一个根节点。系统 MUST NOT 接受第三层节点。名称 MUST 去掉首尾空白后非空；同一个名称或别名 MUST 只属于一个知识点，重复时 MUST 拒绝并返回 400。上级不存在时 MUST 返回 404。

#### Scenario: 建根节点
- **WHEN** 老师建一个没有上级的知识点「氧化还原」
- **THEN** 创建成功，它是根节点

#### Scenario: 建子节点
- **WHEN** 老师在「氧化还原」下面建「氧化剂」
- **THEN** 创建成功，它是第二层节点

#### Scenario: 第三层被拒
- **WHEN** 老师尝试在「氧化剂」下面再建一个节点
- **THEN** 返回 400，不创建节点

#### Scenario: 重名被拒
- **WHEN** 老师建一个与已有知识点同名的节点
- **THEN** 返回 400，不创建节点

#### Scenario: 别名冲突被拒
- **WHEN** 老师把一个别名加到某个知识点上，而该别名已属于另一个知识点
- **THEN** 返回 400，不修改任何知识点

#### Scenario: 上级不存在
- **WHEN** 老师用一个不存在的上级建子节点
- **THEN** 返回 404，不创建节点

### Requirement: 别名与改名
每个知识点 MUST 可以带零到多个别名，别名 MUST 去掉首尾空白后保存，同一个点内重复别名 MUST 去重。修改别名 MUST 用新列表整体替换旧列表。改名时 MUST 把旧名称自动保留为别名，MUST NOT 让旧名称变成无主词。名称和别名 MUST 遵守同一套唯一性规则。

#### Scenario: 保存别名
- **WHEN** 老师给「氧化还原」加上别名「氧化还原反应」
- **THEN** 树里该节点的别名包含「氧化还原反应」

#### Scenario: 改名保留旧名
- **WHEN** 老师把「氧化还原」改名为「氧化还原反应」
- **THEN** 新名称生效，旧名称「氧化还原」成为该节点的别名

#### Scenario: 改名撞上已有词
- **WHEN** 老师把一个知识点改成另一个知识点已有的名称或别名
- **THEN** 返回 400，名称与别名都不变

### Requirement: 题目与知识点多对多
一道题 MUST 可以属于多个知识点，一个知识点 MUST 可以关联多道题。设置一道题的关联时 MUST 用提交的列表整体替换旧关联，列表内重复的知识点 MUST 去重，空列表 MUST 清空关联。只有题目创建者 MUST 能修改这道题的关联，管理员不受限；他人的题 MUST 返回 403。题目或知识点不存在 MUST 返回 404。学生 MUST 返回 403。

#### Scenario: 一道题挂两个点
- **WHEN** 老师把一道题同时挂到「氧化还原」和「电化学」
- **THEN** 两个知识点下都能查到这道题

#### Scenario: 整体替换关联
- **WHEN** 老师把一道题的关联从「氧化还原」改成「电化学」
- **THEN** 这道题只在「电化学」下，不再属于「氧化还原」

#### Scenario: 重复知识点去重
- **WHEN** 提交的关联列表里同一个知识点出现两次
- **THEN** 保存后只有一条关联

#### Scenario: 空列表清空
- **WHEN** 老师提交空的关联列表
- **THEN** 这道题不再属于任何知识点

#### Scenario: 他人的题不能挂
- **WHEN** 老师尝试修改另一位老师创建的题的关联
- **THEN** 返回 403，关联不变

#### Scenario: 学生不能挂知识点
- **WHEN** 学生请求修改任意题的关联
- **THEN** 返回 403，不修改数据

#### Scenario: 题目不存在
- **WHEN** 老师给一道不存在的题挂知识点
- **THEN** 返回 404，不创建关联

### Requirement: 合并知识点
合并 MUST 把一个源知识点并进一个目标知识点，并把源节点删除。目标 MUST NOT 是源自己，MUST NOT 是源的下级；源有子节点且目标本身是子节点时 MUST 拒绝，因为会产生第三层。合并 MUST 把源的别名与源名称一起移到目标，把题目关联移到目标并对重复关联去重，把源的子节点改挂到目标。源节点 MUST 从树中消失，历史统计 MUST 按目标节点重算。源或目标不存在 MUST 返回 404。

#### Scenario: 合并两个根节点
- **WHEN** 老师把「氧化还原」合并进「电化学」
- **THEN** 「氧化还原」的别名、题目关联和子节点都移到「电化学」，「氧化还原」从树里消失

#### Scenario: 源名称成为别名
- **WHEN** 老师把「氧化还原」合并进「电化学」
- **THEN** 「电化学」的别名里包含「氧化还原」

#### Scenario: 题目关联去重
- **WHEN** 源和目标都关联了同一道题，老师执行合并
- **THEN** 目标下这道题只有一条关联

#### Scenario: 合并到自己被拒
- **WHEN** 老师把一个知识点合并到它自己
- **THEN** 返回 400，不修改任何数据

#### Scenario: 合并到下级被拒
- **WHEN** 老师把一个根节点合并进它自己的子节点
- **THEN** 返回 400，不修改任何数据

#### Scenario: 会产生第三层被拒
- **WHEN** 一个有子节点的根节点被合并进另一个根节点的子节点
- **THEN** 返回 400，不修改任何数据

#### Scenario: 源不存在
- **WHEN** 老师合并一个已经不存在或从未存在的知识点
- **THEN** 返回 404，不返回 500，不修改数据

#### Scenario: 目标不存在
- **WHEN** 老师把一个知识点合并进一个不存在的目标
- **THEN** 返回 404，不修改数据

### Requirement: 知识点树的读取
老师与管理员 MUST 能读取完整知识点树，每个节点 MUST 含名称、别名、上级和直接关联的题目数。学生 MUST 返回 403 且不返回知识点数据。读取 MUST NOT 修改任何节点或关联。

#### Scenario: 老师读取整棵树
- **WHEN** 老师请求知识点树
- **THEN** 返回两层结构和每个节点的名称、别名、题目数

#### Scenario: 学生无权读取
- **WHEN** 学生请求知识点树
- **THEN** 返回 403，不返回任何知识点数据
