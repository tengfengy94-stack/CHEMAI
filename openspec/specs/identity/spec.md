# identity Specification

## Purpose

让系统知道"谁是谁"：以一张身份表管理老师、学生、管理员三种账号与班级归属，提供登录、凭证刷新与请求身份解析，作为其余所有模块取"我是谁"的唯一入口。

## Requirements

### Requirement: 一张身份表存三种角色
系统 MUST 以单一账号体系存储 teacher / student / admin 三种身份。学生 MUST 归属且仅归属一个班；老师不挂班级归属；班级 MUST 记录名称与班主任（班主任可带多个班）。账号 MUST 由管理员导入，系统 MUST NOT 提供自助注册；账号 MUST NOT 被删除，身份变化只能通过改归属或改状态完成。

#### Scenario: 学生登录可见班级
- **WHEN** 学生用正确凭证登录
- **THEN** 返回的身份信息包含其所在班级

#### Scenario: 班主任登录可见带的班
- **WHEN** 带两个班的老师登录
- **THEN** 返回的身份信息包含这两个班

#### Scenario: 演示账号就绪
- **WHEN** 系统首次以空库启动
- **THEN** 已存在管理员、带两个班的老师、两个班的学生，均可用预置密码登录

### Requirement: 登录换取凭证
用户 MUST 以用户名加密码登录；成功时返回短期凭证、长期凭证与身份信息。密码错误或用户名不存在时 MUST 拒绝，提示 MUST NOT 透露账号是否存在。

#### Scenario: 登录成功
- **WHEN** 用户名与密码均正确
- **THEN** 返回短期凭证、长期凭证和身份信息（姓名、角色；学生含班级，老师含带的班）

#### Scenario: 密码错误
- **WHEN** 用户名存在但密码错误
- **THEN** 拒绝登录，提示"用户名或密码不对"

#### Scenario: 用户名不存在
- **WHEN** 用户名不存在
- **THEN** 拒绝登录，提示与密码错误时相同

### Requirement: 刷新短期凭证
持有未过期长期凭证的用户 MUST 可换取新的短期凭证；长期凭证无效或已过期时 MUST 拒绝刷新，须重新登录。短期凭证 MUST NOT 被接受用于刷新。

#### Scenario: 刷新成功
- **WHEN** 携带有效长期凭证请求刷新
- **THEN** 返回新的短期凭证

#### Scenario: 长期凭证过期
- **WHEN** 携带已过期的长期凭证请求刷新
- **THEN** 拒绝刷新，提示重新登录

#### Scenario: 短期凭证不能用于刷新
- **WHEN** 携带有效短期凭证请求刷新
- **THEN** 拒绝刷新，提示重新登录

### Requirement: 请求身份解析
携带有效短期凭证的请求 MUST 能解析出当前用户；凭证缺失、伪造或过期时 MUST 拒绝（401），且 MUST NOT 返回任何业务数据。

#### Scenario: 有效凭证解析身份
- **WHEN** 请求携带有效短期凭证
- **THEN** 该请求按凭证对应的用户身份处理

#### Scenario: 凭证过期
- **WHEN** 请求携带已过期的短期凭证
- **THEN** 返回 401，提示重新登录
