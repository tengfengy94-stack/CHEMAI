# Proposal

## Why

ch05 已经接通「交卷 → 同步判分 → 已判分 → 结果态」：三种题型的比较规则、总分公式、判分失败停在已交卷并保留空分、重试只重判，都在 `backend/app/answers.py` 与 `backend/app/routes.py` 里有实现和测试。缺的是判分之后的下一步——学生只能翻每一份卷子看结果，系统没有一份跨卷子的错题清单；而设计 02 §4.8 要求错题按题去重、显示最近一次答错的答案和来源，ch07 的复习队列也要从这里取输入。没有这层，学生回答不了「我到底错过哪些题」，复习也接不上。

## What Changes

- **既有判分基线不重写，只锁定**：单选去首尾空白后相等、多选去空白和分隔符后按集合完全相等（漏选/多选不得分）、填空全角转半角并去掉所有空格后比原文且大小写敏感；总分 = 正确题数 ÷ 卷子总题数 × 100，保留一位小数；已交卷 → 已判分的同步转移与失败重试。以上沿用现有实现，本次用回归测试和验收清单确认错题功能不会改变它们。
- **新增错题清单查询**：`GET /api/wrong-questions` 从已判分的 `answer_items` 里取 `is_correct=false` 的记录，按「学生 + 题目」去重，只保留每名学生最近一次答错的那条；返回题干、选项、学生答案、标准答案、解析、来源、卷子标题和最近答错时间，管理员视角另带学生身份用于区分。
- **错题不新增表**：按设计 02 §2，错题就是逐题作答里答错的那部分，一次查询即可得到；另存一份会出现两处不一致。答对不会把题移出清单，移出是复习队列的职责。
- **结果与错题两个动作**：保留已判分记录的「查看结果」，在结果态增加「看错题」；错题清单以抽屉形式在当前考试页打开，不新增页面、不破坏考试页「列表 / 作答 / 结果」三态，并覆盖加载、空、出错三种页面状态。
- **未判分记录不产生错题**：`已交卷 + 空分` 或 `is_correct` 为空的记录不进入清单；错题只在判分完成后可见。
- **权限沿用现有结果范围**：学生只能看自己的错题，管理员可以看全部；老师按班查看错题留给班级报告章节，与现有结果入口保持一致。
- **不在本次范围**：复习排期与出队、练习错题、错题重做、班级报告、错题导出。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `exam`: 新增错题清单的按题去重、最近一次答案、来源、排序与可见范围，以及已判分结果态的「看错题」动作；现有判分比较、总分计算和状态机需求不变。

## Impact

- **后端**：`backend/app/routes.py` 新增 `GET /api/wrong-questions`，复用 `AnswerItem / AnswerRecord / Question / Paper` 查询并做角色过滤；`backend/tests/` 补错题去重、最新答案、排序、答对不移除、未判分排除和权限用例。无新表、无 Alembic 迁移。
- **前端**：`frontend/src/api.js` 增加错题接口；`frontend/src/pages/student/Exams.jsx` 结果态增加「看错题」按钮与抽屉，已判分行继续使用「查看结果」。
- **数据**：`chemai.db` 不需要迁移，原有作答与判分数据直接可查。
- **接口契约**：继续使用 `{success, data, error}` 信封；错题接口是新增只读接口，交卷、判分、重试与结果详情接口契约不变。
