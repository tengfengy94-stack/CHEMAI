# Proposal

## Why

第 12 章已经能按场景拼提示词并调用工具，但设计 04 §4.5–§4.6 的两层护栏还缺一半：人设只有引导型、讲解型两档，没有按连续答错触发的鼓励型；四条红线只写在系统提示里，回答生成后没有输出检查。结果是练习场景可能被追问出答案、模型可能编造其他学生姓名、危险实验建议和贬低表达没有第二道拦截。这一章补齐三种人设、连续答错计数读取和四条红线的输出护栏。

## What Changes

- **人设切换**
  - 场景仍由入口带进请求（`practice` / `wrong` / `chat`），服务端按场景选引导型或讲解型；老师固定讲解型，不套学生的三种人设。
  - 新增鼓励型：学生最近连续答错 ≥3 时，在场景人设之后**叠加**鼓励段（先接住情绪，建议更简单的下一步），保留练习场景“不直接给答案”和错题场景“先讲错因”的原规则。
  - 连续答错次数从 `practice_records` 现查：按记录倒序数尾部连续 `is_correct=false` 的条数，答对一条清零；不放在内存，不依赖对话历史。
- **系统提示**
  - 四段顺序固定为身份与范围、场景人设（含鼓励叠加）、四条红线、输出要求；考试中的学生额外插入考试约束段。
  - 四条红线写死在提示里：不代替考试作答、不泄露其他学生信息、不给危险实验建议、不使用羞辱贬低表达。
- **输出检查**
  - 在 SSE 文本路径按句/小段缓冲；每个片段用规则检查四条红线（禁词、危险操作模式、其他学生姓名或分数模式、考试中答案模式）。
  - 命中后丢弃该片段及后续模型正文，按红线输出对应的拒绝、安全提示或中性重写，然后正常发 `end`；不额外调用模型。
  - 工具层继续只返回当前身份可见数据，输出检查只兜底模型自编内容。
- **拒绝话术**统一为“说明为什么不行 + 接下来能做什么”，覆盖考试中问答案、问别人成绩、危险操作三类。
- **明确不做**：AI 出题、AI 判分、改分改答案、向量记忆、第二套智能体或接口；不改变现有 SSE 的 `tool` / `text` / `end` 事件契约和前端页面结构。

## Capabilities

### New Capabilities

- `agent-guard`: 助教回答的安全护栏——四条红线的系统提示约束、句级缓冲的输出检查、命中后的拒绝或重写、考试中与跨学生数据的兜底。

### Modified Capabilities

- `agent-chat`: 场景人设从两档扩展为引导型、讲解型、鼓励型（鼓励型按连续答错叠加），新增连续答错计数的读取与刷新语义。

## Impact

- 后端：`agent_context.py` 增加连续答错字段与提示拼装；`agent_runtime.py` 或新增护栏模块挂输出检查；`agent_routes.py` 的 SSE 文本路径改为句级缓冲并在命中时收尾；`practice.py` 增加连续答错计数；`agent.py` 假模型可产生违规文本用于测试。
- 接口：`POST /api/chat/stream` 请求与响应字段不变；`text` 事件仍是增量，但发送粒度从 token 变为句或小段；`end` 语义不变。
- 数据：无表结构变更，只新增对 `practice_records` 的只读查询。
- 测试：新增三档人设、连续答错计数、四条红线输出检查、拒绝话术与流式收尾的测试；现有 350 条保持全绿。
