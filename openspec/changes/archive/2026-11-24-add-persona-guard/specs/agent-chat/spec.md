# Spec Delta

## MODIFIED Requirements

### Requirement: 场景人设

请求 MUST 带场景：从练习页进入为练习场景，从错题页进入为错题场景，直接打开对话页为普通对话场景。服务端 MUST 按场景选择人设提示，MUST NOT 让模型自己猜场景。学生连续答错 ≥3 次时，场景人设 MUST 追加鼓励段（先接住情绪、建议更简单的下一步），且 MUST NOT 取消原场景的约束。老师 MUST 不套学生的三种人设，统一按讲解型严谨口径回答，MUST NOT 出现鼓励型话术。

#### Scenario: 练习场景不给答案
- **WHEN** 学生从练习页点"问一句"进入并问当前题
- **THEN** 助教按引导型人设一次只给一个提示，不直接说选哪个

#### Scenario: 错题场景先讲错因
- **WHEN** 学生从错题页进入并问"为什么错"
- **THEN** 助教按讲解型人设先讲错因，再讲正确思路，最后给一道同类题

#### Scenario: 老师不套学生人设
- **WHEN** 老师从对话页问班级问题
- **THEN** 助教按讲解型严谨口径回答，不使用鼓励型话术

#### Scenario: 场景入口跟着走
- **WHEN** 学生从练习页或错题页点击"问一句"
- **THEN** 对话页收到对应场景，不把它当成普通对话

#### Scenario: 连续答错触发鼓励
- **WHEN** 学生最近连续答错 3 条练习记录后发起下一次对话
- **THEN** 场景人设之后追加鼓励段，回答先接住情绪，再给一个更简单的下一步

#### Scenario: 鼓励不放松场景纪律
- **WHEN** 学生在练习场景且连续答错 3 次
- **THEN** 仍一次只给一个提示，不直接说选项或最终答案

#### Scenario: 答对一条清零
- **WHEN** 连续答错 3 次后学生答对一条练习
- **THEN** 下一次对话恢复场景原人设，不再追加鼓励段

#### Scenario: 换设备计数仍在
- **WHEN** 学生刷新页面或换设备后发起对话
- **THEN** 服务端从练习记录得到相同的连续答错次数

## ADDED Requirements

### Requirement: 连续答错计数从练习记录现查

服务端 MUST 在每次学生对话请求开始时从练习记录现查连续答错次数：按记录先后顺序数最近一段连续答错，遇到答对一条即停止并归零。计数 MUST NOT 取自对话历史、摘要或进程内存；刷新页面或换设备后 MUST 得到相同结果。老师与管理员 MUST NOT 计算该计数。

#### Scenario: 尾部连续三条答错
- **WHEN** 学生最近三条练习记录都是答错
- **THEN** 连续答错次数为 3

#### Scenario: 中间答对一条
- **WHEN** 学生在连续答错之间答对过一条
- **THEN** 只数最近一次答对之后的连续答错

#### Scenario: 没有练习记录
- **WHEN** 学生从未做过练习
- **THEN** 连续答错次数为 0，不触发鼓励型

#### Scenario: 老师没有该计数
- **WHEN** 老师发起对话
- **THEN** 不计算也不使用连续答错次数
