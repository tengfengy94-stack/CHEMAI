# Proposal

## Why

前十个章节把题库、考试、判分、复习、报告都做完了，但 Agent 模块还一行代码都没有。设计 04 §4.1 要求 Agent 由模型、工具、系统提示、中间件、循环五部分组成；这一章先把其中最底层的一条竖线打通：能连上模型、能流式吐出文字、能在一个页面上看见。没有这条竖线，后面的工具、人设、护栏、评测都没有落点。

模型服务不可能每次开发都在线，所以假模型开关和真模型一样是这一章的一等公民：没有密钥时整套流程也要能跑通、能测试。

## What Changes

- 新增后端 Agent 对话能力：
  - 模型客户端抽象：真模型走 OpenAI 兼容协议（地址、模型名、密钥来自环境变量），假模型用固定中文回答逐字输出，不联网、不需要密钥。
  - `POST /api/chat/stream`：登录后可调用，接收一句话，返回 SSE 流；流里只有 `text`（逐字正文）与 `end`（本轮结束）两类事件。
  - 响应带防缓冲头，每 15 秒发一次心跳；流开始前的失败走统一 JSON 信封，流中断时直接关流、不发 `end`。
  - 最小系统提示（身份与范围）；人设、红线、工具描述留给后续章节。
- 新增前端对话页 `/student/chat`：学生与老师共用；消息列表 + 输入框，发送中禁用输入框，正文逐字追加，结束时恢复；覆盖空、发送中、流式回答、出错四态。
- 学生端与老师端导航各加一个“对话”入口。
- 依赖新增 `langchain-openai`；不引入 LangGraph（本章没有工具循环，等工具章节再上）。

**明确不做**：
- 不接任何工具，不产生 `tool` 事件，不建工具调用循环。
- 不存历史：不建对话表、不写对话存档、不提供历史接口；每轮请求只带当前这一句话，刷新页面即清空。
- 不做三种人设、四条红线、输出检查、评测集。
- 不做多轮上下文、历史压缩、跨对话记忆。

## Capabilities

### New Capabilities

- `agent-chat`: 登录用户与助教的一轮流式对话——模型客户端（真/假切换）、SSE 事件、防缓冲、最小系统提示；不含工具与历史。

## Impact

- 后端：新增 Agent 模块与对话路由；`backend/requirements.txt` 增加 `langchain-openai`；`backend/app/config.py` 增加模型配置读取；`backend/app/main.py` 挂载路由。
- 前端：新增 `pages/student/Chat.jsx`；`App.jsx` 增加共用路由；学生与老师页头增加入口；`api.js` 增加能带 Authorization 的流式读取函数（不能复用只解析 JSON 的 `request()`）。
- 接口：新增 `POST /api/chat/stream`，是现有 `{success, data, error}` 信封的唯一例外（流本身不是 JSON）。
- 数据：无迁移、无新表。
- 测试：新增模型客户端与流式接口测试；现有 288 条测试必须保持全绿。
