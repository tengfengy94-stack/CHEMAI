# Design

## Context

- 当前仓库没有 Agent 模块：`backend/app/` 只有题库、考试、复习、报告等业务函数，`requirements.txt` 里没有 LangChain 系依赖；前端九个页面里没有对话页。
- 已有可复用的约定：所有 JSON 接口走 `app/envelope.py` 的 `{success, data, error}`；鉴权用 `get_current_user` 依赖；路由统一挂在 `/api`；前端 `api.js` 的 `request()` 只解析 JSON，遇到 401 会静默续签并重放。
- 设计约束：04 §4.1 的模型、工具、提示、中间件、循环五件套；04 §4.7 的三类事件、防缓冲、15 秒心跳、fetch 读流；05 §4.7 的 LangChain + LangGraph 选型。
- 本章范围（见 proposal.md）：只做模型客户端、流式对话、对话页；不接工具、不存历史。

## Goals / Non-Goals

**Goals:**

- 打通“登录 → 发一句话 → SSE 逐字返回 → 页面渲染”的竖线。
- 无密钥、无网络时也能完整跑通并被自动化测试覆盖。
- 流式接口的行为（事件、顺序、响应头、心跳、失败路径）可被测试直接断言，而不是靠肉眼看。

**Non-Goals:**

- 不引入 LangGraph，不建图、不建工具节点、不产生 `tool` 事件。
- 不建对话表、不写对话存档、不提供历史接口、不做多轮上下文。
- 不做人设切换、四条红线、输出检查、评测集。
- 不做 Markdown/公式渲染，回答按纯文本显示。

## Decisions

### 决策 1：本章只用 `langchain-openai`，不上 LangGraph

理由：没有工具就没有“模型想—调工具—再想”的循环，单次模型调用用 `ChatOpenAI.astream` 足够；现在建一个只有模型节点的图，是给后续章节提前付复杂度。工具章节再引入 LangGraph，并把流式读取从 `ChatOpenAI.astream` 换成图的消息流，页面协议不变。

备选：现在就建单节点 LangGraph。被否，原因如上。

### 决策 2：接口单轮无状态，请求只带一句话

`POST /api/chat/stream` 的请求体只有一个字段：`{"message": "..."}`。服务端不接收 `history`、不建会话 ID、不落库。每一轮都把“最小系统提示 + 当前这句话”发给模型。

备选：前端传消息数组。被否——用户明确选择“每轮独立”，且后续接框架记忆时接口会再变一次，现在多做的部分会白扔。

### 决策 3：SSE 线格式，前端用 fetch 读，不用 EventSource

响应是 `text/event-stream`，前端用 `fetch` + `response.body.getReader()` 读。理由：EventSource 不能带 `Authorization` 头，也不能带请求体（04 §4.7）；现有 JWT 凭证只能走 fetch。

事件编码：

```
event: text
data: {"delta":"你最近三次考试里，"}

event: text
data: {"delta":"氧化还原相关的题错了 4 道。"}

event: end
data: {}

: ping
```

- `text` 的 `data` 用 JSON 包一层，避免正文里的换行破坏 SSE 分帧。
- `end` 的 `data` 固定为 `{}`，前端只关心事件名。
- 心跳是 SSE 注释行 `: ping`，不是事件，解析器会忽略；不计入 `text` 或 `end`。
- 前端按 `\n\n` 切帧，跨网络包的半帧先缓冲，不能假设一次 `read()` 就是一整帧。

备选：NDJSON。也能流式，但设计里的“心跳”“事件源”语义都更贴近 SSE；且 `text/event-stream` 对中间层更标准。

### 决策 4：模型配置与假模型选择

配置全部走环境变量，沿用 `config.py` 的风格：

| 变量 | 作用 | 缺省 |
|---|---|---|
| `CHEMAI_FAKE_MODEL` | 显式开启假模型，`1`/`true` 生效 | 关 |
| `CHEMAI_MODEL_API_KEY` | 真模型密钥 | 无 |
| `CHEMAI_MODEL_BASE_URL` | OpenAI 兼容地址 | 无 |
| `CHEMAI_MODEL_NAME` | 模型名 | 无 |

选择顺序：

1. `CHEMAI_FAKE_MODEL` 开启 → 假模型。
2. 没有 `CHEMAI_MODEL_API_KEY` → 自动假模型，并打一条警告日志（对应 04 §五“没有配模型密钥：假模型照常跑通”）。
3. 有密钥但地址或模型名缺失 → 视为配置错误，在建立流之前返回 500 JSON 信封，不静默降级——生产环境配错了要能看见。
4. 配置齐全 → `ChatOpenAI(base_url=..., api_key=..., model=..., streaming=True)`。

假模型是一个异步生成器，按固定中文回答分多段 `yield`，不发起任何网络请求；段间留一个可配置的短延迟（默认 20ms，测试设 0），让页面上的逐字效果可见但不拖慢测试。

### 决策 5：流式路由要绕开两处现有机制

**统一信封**：`/api/chat/stream` 成功时直接返回 `StreamingResponse`，不经过 `ok()`。失败发生在流开始之前时仍返回 `fail()` 的 JSON 信封，保持“非流式错误一律是信封”的约定。

**请求级数据库会话**：FastAPI 的 `get_current_user` 依赖带 `yield` 会话，流式生成器可能在依赖清理之后才继续执行。生成器里 MUST NOT 再碰 ORM 对象或会话；在返回 `StreamingResponse` 之前，把 `username`、`role` 等需要的值取成普通字符串。

生成器内部自己捕获异常：一旦响应已经开始，全局异常处理器无法再把异常换成 JSON 信封；正确做法是记日志、结束生成器、让连接关闭，且不发 `end`。

### 决策 6：心跳用“模型增量与超时赛跑”实现

一个异步生成器里同时等待两件事：模型的下一个增量、15 秒超时。谁先到就处理谁：

```
loop:
  wait(model_anext, timeout=15s)
    ├─ 模型增量 -> 发 text
    ├─ 模型结束 -> 发 end，退出
    └─ 超时     -> 发 ": ping"，继续等
```

超时值做成模块常量，测试可以调小来验证心跳，不必真等 15 秒。生成器退出前要取消未完成的模型任务，避免上游连接泄漏。

### 决策 7：最小系统提示先立住，不提前做人设

系统提示只写“身份与范围”一段：你是这门课的化学助教，只回答这门课的问题；不确定就说不确定。场景人设、四条红线、输出要求留给后续章节。每次请求固定两条消息：`system` + 当前 `user`，不拼接历史。

### 决策 8：前端流解析独立于页面

`api.js` 增加 `streamChat(message, { signal, onEvent })`：

- 复用现有 `loadAuth()` 取 token；401 时复用一次刷新逻辑再重试（流还没开始时才能重试），仍失败则清凭证跳登录。
- 非 2xx 先读 JSON 信封，抛 `ApiError`。
- 2xx 读 `response.body`，按 SSE 帧解析，回调 `onEvent({event, data})`；`signal` 用于离开页面时 abort。
- 不把 SSE 解析写进 `Chat.jsx`，页面只消费事件。

页面状态机：

```
空对话 --发送--> 发送中 --text--> 流式回答 --end--> 发送中结束，恢复输入
                    |                  |
                    +---- 出错 --------+--> 出错（保留已收到文字，可重试）
```

- 消息在 React state，不写 localStorage/sessionStorage；刷新即空。
- 发送中禁用输入框与发送按钮；发送按钮同时承担“发送”和“重试”。
- 只有 `text` 追加到当前 assistant 气泡；`end` 结束本轮；没有 `end` 的异常关闭按出错处理。

### 决策 9：对话页路由共用，入口两端都加

路由 `/student/chat`，`RequireAuth` 放行 `student`、`teacher`、`admin`——页面共用，服务端本章不按角色裁剪回答。学生 `StudentHeader` 加“对话”按钮；每个老师页头加“对话”按钮。老师沿用学生路径，不另开 `/teacher/chat`（05 §4.1）。

### 决策 10：测试以流式协议为主，前端靠构建加走查

- 后端 pytest：
  - 用 `TestClient.stream()` 读原始行，断言事件顺序、`end` 唯一、响应头、空消息 422、未登录 401。
  - 假模型固定回答，断言拼接后的正文等于预期，且多段到达。
  - 通过可注入的模型工厂模拟“中途失败”，断言没有 `end`。
  - 测试期间不需要网络和真实密钥。
- 前端：`npm run build` 必须通过；页面四态与流式追加用浏览器走查（项目现有做法），不新增前端测试框架。

## Risks / Trade-offs

- **没有多轮上下文**：学生追问“好”“为什么”时模型接不住。 → 本章明确接受，页面上不暗示能连续追问；记忆章节再补。
- **真模型服务商差异**：不同 OpenAI 兼容服务的流式分块、错误格式不完全一致。 → 统一走 LangChain 的 `ChatOpenAI`，假模型保证离线路径；真模型只做最小冒烟。
- **心跳与增量赛跑的实现容易泄漏任务**：超时分支反复创建/取消任务可能留下未关闭的上游连接。 → 生成器 `finally` 里统一取消，并为心跳单独写测试。
- **依赖版本未锁**：`langchain-openai` 的版本会和 Python 3.12、现有 Pydantic 2 互相约束。 → 安装后把精确版本写进 `requirements.txt`，先跑一遍全量测试再继续。
- **流式响应绕开统一信封**：客户端现在有两种成功响应形态（JSON 与 SSE）。 → 只有这一个接口例外；失败仍走信封，前端 `streamChat` 单独处理，不影响现有 `request()`。
- **无频率限制**：真模型下连续点击会持续产生费用。 → 本章是本地单机、发送中禁用输入框已经挡住连点；限流留给后续。

## Migration Plan

- 无数据库迁移、无新表。
- 部署变更：安装新增依赖；按需配置四个模型环境变量。不配置密钥时自动假模型，现有功能不受影响。
- 回滚：移除对话路由与页面即可，不涉及数据回滚。
