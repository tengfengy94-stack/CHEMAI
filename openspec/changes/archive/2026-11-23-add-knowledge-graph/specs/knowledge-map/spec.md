# Spec Delta

## ADDED Requirements

### Requirement: 老师端知识点管理页
老师与管理员 MUST 能打开知识点管理页并看到完整两层树，每个节点 MUST 显示名称、别名和直接题目数。页面 MUST 支持新建根节点、新建子节点、修改名称与别名、合并节点，并 MUST 从题库页与考试页可达。所有写操作 MUST 沿用既有校验；失败时 MUST 显示中文原因且不修改数据。学生 MUST 不能进入该页，后端 MUST 返回 403。页面 MUST 覆盖加载、空、正常、出错四态，空树 MUST 显示新建入口。

#### Scenario: 老师查看两层树
- **WHEN** 老师打开知识点管理页
- **THEN** 页面按根节点与子节点展示名称、别名和直接题目数

#### Scenario: 空树给新建入口
- **WHEN** 系统里还没有任何知识点
- **THEN** 页面显示「还没有知识点」和「新建第一个知识点」按钮

#### Scenario: 新建子节点
- **WHEN** 老师在某个根节点下新建子节点
- **THEN** 新节点出现在该根节点下，页面刷新后仍在

#### Scenario: 合并前说明去向
- **WHEN** 老师选择源节点和目标节点执行合并
- **THEN** 确认框 MUST 写明源的别名、题目关联和子节点会移到目标，源节点会消失

#### Scenario: 非法合并不写库
- **WHEN** 老师尝试把节点合并到它自己或它的下级
- **THEN** 页面显示中文原因，树不发生变化

#### Scenario: 学生不能进入
- **WHEN** 学生访问知识点管理页或知识点接口
- **THEN** 前端不渲染管理页，后端返回 403 且不返回知识点数据

#### Scenario: 加载失败可重试
- **WHEN** 知识点树加载失败
- **THEN** 页面显示固定错误文案和重试按钮，不显示原始报错

### Requirement: 正式两层知识词表
系统 MUST 提供一套正式的两层知识词表：根节点为氧化还原、电化学、化学平衡、物质结构、元素周期律；氧化还原下 MUST 有氧化剂和还原剂。正式节点的名称与别名 MUST 遵守既有全局唯一规则，MUST NOT 绕过第三层校验。重复执行种子写入 MUST NOT 重复创建同名节点。

#### Scenario: 正式词表齐全
- **WHEN** 正式词表写入完成
- **THEN** 树中恰好有五个根节点，氧化还原下有氧化剂和还原剂

#### Scenario: 种子幂等
- **WHEN** 正式词表已经存在，再次执行种子写入
- **THEN** 节点数量不变，不产生重复名称或重复别名

### Requirement: 临时知识点归并
升级时 MUST 把第 07 章遗留的临时知识点按名称或别名映射到正式词表。命中的临时节点 MUST 按合并语义把别名、题目关联和子节点并入正式节点，并在合并后删除临时节点。未命中的临时节点 MUST 保留为正式节点，同时写入迁移报告，MUST NOT 静默删除。迁移 MUST 幂等、MUST 支持 dry-run（只报告不写库），MUST 在单个事务内完成；任一步失败 MUST 回滚全部改动。

#### Scenario: 命中后源节点消失
- **WHEN** 临时节点「电解质」按映射并入正式节点「电化学」
- **THEN** 「电解质」从树中消失，它的别名和题目关联出现在「电化学」下

#### Scenario: 重复关联去重
- **WHEN** 源节点和目标节点都关联了同一道题，迁移执行合并
- **THEN** 目标节点下这道题只有一条关联

#### Scenario: 未命中节点保留
- **WHEN** 某个临时节点的名称和别名都不在正式词表里
- **THEN** 该节点保留在原位置并成为正式节点，迁移报告列出它的名称

#### Scenario: 重复执行无副作用
- **WHEN** 迁移已经成功执行过一次，再次执行
- **THEN** 树结构与题目关联不变，报告不再列出已归并的临时节点

#### Scenario: dry-run 不写库
- **WHEN** 以 dry-run 方式执行迁移
- **THEN** 输出与正式执行相同的迁移报告，但节点、别名和题目关联都保持不变

#### Scenario: 失败整体回滚
- **WHEN** 迁移过程中任一步出错
- **THEN** 本次迁移的全部节点、别名和关联改动回滚，数据库保持迁移前状态

### Requirement: 迁移后的弱项统计口径
迁移后，同一道题与同一个概念的关联 MUST 仍然只计一次；弱项统计 MUST 按合并后的正式节点重新汇总，MUST NOT 因为节点改名或合并而重复计数，也 MUST NOT 丢掉原先计入的题目。复习作答 MUST 继续不进弱项口径。

#### Scenario: 按正式节点汇总
- **WHEN** 两个知识点各有作答，其中一个并入另一个后学生刷新弱项
- **THEN** 作答数与错题数汇总到正式节点，临时节点不再出现

#### Scenario: 题目关联数守恒
- **WHEN** 迁移把临时节点的题目关联移到正式节点
- **THEN** 同一道题关联的概念数量与迁移前一致，没有重复行

#### Scenario: 复习作答不计入
- **WHEN** 学生完成一次复习作答后刷新弱项
- **THEN** 复习作答不改变弱项的错误率、作答数或错题数
