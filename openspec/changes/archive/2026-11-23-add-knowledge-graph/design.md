# Design

## Context

- 第 07 章已交付知识点后端最小闭环：`knowledge_points`、`knowledge_point_aliases`、`question_knowledge_points` 三张表，`GET/POST/PUT /api/knowledge-points`、`POST /api/knowledge-points/{id}/merge`、`PUT /api/questions/{id}/knowledge-points`，以及 `openspec/specs/knowledge-map/spec.md`。本变更在这些接口之上补管理页与数据迁移，不重做接口。
- `GET /api/knowledge-points` 的树节点已含 `id`、`name`、`parent_id`、`aliases`、`question_count`、`children`，管理页不需要新增读接口。
- 前端是 React + antd，页面各自渲染页头；老师页已有 `/teacher/questions` 与 `/teacher/exams`，`api.js` 统一拆信封并处理 401 刷新。
- 开发库 `chemai.db` 有第 07 章验收走查时临时建的 4 个知识点：氧化还原（根，别名「氧化还原反应」）、氧化剂（氧化还原的子节点）、电解质（根，别名「电离」）、化学式与化合价（根，别名「化学式」）；题目关联共 3 条。
- 测试每个用例一份临时库，用 Alembic 建结构；迁移逻辑要能在同一个 Session 上跑，不依赖开发库。

## Goals / Non-Goals

**Goals:**

- 老师能在界面上维护两层知识点树：看、建、改名称/别名、合并。
- 用一份固定的正式词表收拢第 07 章的临时知识点；命中合并、未命中保留并报告。
- 迁移可 dry-run、幂等、单事务、可回滚；迁移后弱项统计按正式节点重算且不丢题、不重复计数。
- 不改变现有接口契约与表结构。

**Non-Goals:**

- 不引入三级树、跨分支关系、图数据库或图查询。
- 不做知识点删除接口；合并是唯一会删除节点的路径。
- 不做学生端知识点浏览、题目按知识点筛选、自动近义词合并。
- 不把迁移做成 Alembic 版本；它是数据整理命令，不是表结构变更。

## Decisions

### 1. 管理页复用现有接口，不新增端点

树读取、建节点、改名称/别名、合并四件事都已经有接口。管理页只需要在 `api.js` 增加四个封装，不需要新增后端路由。备选方案是加一个「管理页专用」聚合接口，但会让同一份行为有两套契约，收益为零。

### 2. 合并目标的合法性由同一套规则驱动

前端在合并弹窗里禁用非法目标，规则与 `knowledge.merge_points` 完全一致：

- 目标不能是源自己；
- 目标不能是源的直接子节点（两层树下「自己的下级」就是直接子节点）；
- 源有子节点时，目标必须是根节点，否则会出现第三层。

前端禁用只是体验，后端 400 仍是最终判定。确认框固定写清「源的别名、题目关联和子节点会移到目标，源节点会消失」，避免老师把合并当成删除。

### 3. 正式词表与临时标签映射

正式词表放在 `backend/app/knowledge_seed.py`，结构与第 07 章验收时的实际数据对齐：

| 正式根节点 | 正式子节点 |
|---|---|
| 氧化还原 | 氧化剂、还原剂 |
| 电化学 | — |
| 化学平衡 | — |
| 物质结构 | — |
| 元素周期律 | — |

临时标签映射（按名称或别名匹配，源节点合并后删除）：

| 第 07 章临时节点 | 已有别名 | 并入正式节点 | 结果 |
|---|---|---|---|
| 氧化还原 | 氧化还原反应 | 氧化还原 | 名称已匹配，保留节点与别名 |
| 氧化剂 | — | 氧化剂（氧化还原下） | 名称已匹配，保留节点 |
| 电解质 | 电离 | 电化学 | 别名与题目关联移到电化学，删除电解质 |
| 化学式与化合价 | 化学式 | 物质结构 | 别名与题目关联移到物质结构，删除化学式与化合价 |

把「电解质」「化学式与化合价」并到更大的根节点，而不是新建同名的子节点，原因有两个：第 07 章的这两个节点是走查时临时起的名字，不是正式层级；弱项统计只需要能回答「哪一块弱」，粗到「电化学」「物质结构」已经够用。代价是这两个词会变成根节点的别名，日后如果老师要在电化学下单独建「电解质」子节点，需要先从别名里移除它。这个代价写进迁移报告，由老师决定是否接受。

映射表是显式数据，不靠模糊匹配；改名或加映射只改这一张表。

### 4. 迁移是独立命令，不进 Alembic

新增 `backend/app/knowledge_migrate.py`，提供 `run_migration(session, dry_run=False) -> dict` 和命令行入口：

```bash
.venv/Scripts/python.exe -m app.knowledge_migrate --dry-run
.venv/Scripts/python.exe -m app.knowledge_migrate --apply
```

理由：没有表结构变更；合并会删除源节点，downgrade 无法把已删除的节点与关联恢复原样，把它塞进 Alembic 会制造一个假的可逆性。命令在单个事务里完成，失败全部回滚；回滚手段是迁移前备份 `chemai.db`。

`run_migration` 先只读地算出一份计划（要建哪些正式节点、哪些临时节点命中/未命中、会移动多少别名与题目关联、有没有唯一词冲突），dry-run 直接返回这份计划；apply 在同一事务里执行计划。重复执行时正式节点已存在、临时节点已消失，计划为空，天然幂等。

### 5. 合并逻辑抽出可复用内部函数

`knowledge.merge_points` 现在每次调用都 `commit()`。迁移需要把多次合并放进一个事务，所以把主体抽成 `_merge_points(session, source, target)`（不提交），公开的 `merge_points` 保持原签名并继续在末尾提交。API 行为与现有测试不变；迁移在 `session.begin()` 里连续调用内部函数，最后一次提交，异常时整体回滚。

正式节点的创建同样走内部、不提交的路径（`_create_point` 或直接构造 `KnowledgePoint`），`created_by` 写 `"system"`。

### 6. 唯一词冲突在写入前预检

名称与别名全局唯一。迁移要把源节点的名称和别名塞进目标，可能与目标已有词或第三方节点冲突。执行计划阶段先算出目标合并后的完整词表，与全局词表比对；发现冲突就带着冲突清单中止，apply 不写任何一行。dry-run 同样列出冲突，老师先改映射或先手工处理冲突，再执行。

### 7. 迁移报告

`run_migration` 返回并打印中文报告，至少包含：

- 新建的正式节点；
- 合并的临时节点及目标；
- 保留的未命中节点；
- 移动的别名与题目关联数；
- 冲突清单；
- `dry_run` 标记与是否实际写入。

报告是验收证据：`tasks.md` 里的开发库迁移验收直接引用这份输出。

### 8. 管理页用表格树，不用独立 Tree 组件

antd `Table` 支持 `children` 展开，列固定为「名称 / 别名 / 题目数 / 操作」，操作列提供「编辑」「合并」「建子节点」（仅根节点显示）。相比 `Tree` + 右侧详情，表格与项目现有题库、考试页的交互一致，别名和题目数也能直接成列。页面覆盖加载、空、正常、出错四态；空态给「新建第一个知识点」，出错态只给固定文案和重试，不显示原始报错。

## Risks / Trade-offs

- **[映射语义有争议]** 「电解质 → 电化学」「化学式与化合价 → 物质结构」是按教学范围做的粗归类，不是唯一正确答案。→ 映射表显式列出，dry-run 报告先给老师确认；要改只改 `knowledge_seed.py` 的一张表，apply 前可反复 dry-run。
- **[合并删除不可逆]** 合并会删除源节点。→ 开发库迁移前备份 `chemai.db`；迁移单事务，失败整体回滚；测试覆盖回滚路径。
- **[别名冲突导致迁移中止]** 目标已有同名或同别名节点时，迁移不会硬写。→ 预检阶段列出冲突并中止，老师先清理冲突再跑。
- **[弱项报告的知识点名字会变]** 原本按「电解质」「化学式与化合价」统计的题，迁移后归到「电化学」「物质结构」。→ 这是预期行为；验收时对比每道题关联的概念数守恒，并确认同一批题仍被计入。
- **[正式词表只是这一版的教学范围]** 五个根节点覆盖不了所有化学内容。→ 词表是种子不是白名单；老师仍可在管理页建新根节点，未命中节点也会保留。

## Migration Plan

1. 备份开发库：复制 `chemai.db` 为 `chemai.db.bak`。
2. 跑 `python -m app.knowledge_migrate --dry-run`，核对新建、合并、保留、冲突四类清单。
3. 确认后跑 `--apply`，检查树：氧化还原（氧化剂、还原剂）、电化学、化学平衡、物质结构、元素周期律；电解质与化学式与化合价消失。
4. 对比迁移前后每道题的关联概念数；请求学生弱项报告，确认题目仍计入、无重复行。
5. 再跑一次 `--dry-run`，确认计划为空（幂等）。
6. 回滚：停服务，用 `chemai.db.bak` 覆盖 `chemai.db`，重启。没有 Alembic downgrade。
