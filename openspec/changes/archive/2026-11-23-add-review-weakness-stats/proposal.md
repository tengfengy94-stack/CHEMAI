# Proposal

## Why

ch05 与 ch06 已经接通「交卷 → 判分 → 错题清单」，但错题只回答"过去错过什么"，不回答"接下来哪天再做一次"；系统也没有知识点归类，报告只能看到分数，说不出"哪一块弱"。设计 03 的闭环是错题入队、按间隔复习、再按知识点汇总弱项，本次把这条线接上。

## What Changes

- **复习队列**：一个学生对一道题只有一条复习任务，级别 0–5。判分完成时，每道答错的题入队为第 0 级、明天到期；同一道题在新考试里再答错，级别归零、不新增任务；第 5 级出队但任务保留，不出现在到期列表。
- **到期列表**：只列本地"今天及以前"到期的任务，按到期日升序排列；逾期不清零、不降级、不标红，晚做不惩罚。
- **复习作答**：服务端用与考试同一套 `judge_answer` 判分，不自评。答对升一级，按新级别间隔重排（1 级 3 天、2 级 7 天、3 级 14 天、4 级 30 天，5 级出队）；答错回第 0 级、明天再来。结果显示学生答案、标准答案、解析和上次答案。同一天可对同一任务再答一次，照常判、照常升降。
- **知识点最小闭环**：新增两层知识点（学科大点 / 具体点）、别名、题目多对多关联，以及建、改、树读取、合并接口。合并把源节点的别名、题目关联和子节点移到目标节点并删除源节点；拒绝合并到自己、合并到自己的下级，以及会产生三层的合并。统计只读关联，不读缓存。
- **弱项前三**：按知识点汇总已判分考试的逐题作答。错误率 = 错题数 ÷ 作答数，同一道题答多次各算一次，只取作答数不少于 2 的前三名；一道题挂多个知识点时，在每个知识点的分母里各算一次；未挂知识点的题、未判分记录不参与。**本次不接练习记录**：练习模块尚未实现，等练习落地后用同一口径合并，本次不建练习表。
- **历史错题回填**：迁移时为已经判分、答错的逐题作答补建第 0 级复习任务，同一学生同一道题取最近一次判分；旧任务可能一开始就是逾期状态，按逾期规则照常列出，不修改原有分数与作答。
- **权限**：学生只能看和回答自己的复习任务；老师无复习入口；管理员可读全部任务但不能代替学生作答。知识点是共享词典，任何老师可建、改、合并；题目挂载仍只能挂自己创建的题，管理员不受限。
- **前端**：新增学生复习页（"今日到期"与"全部错题"两个页签、答题态、判分结果），新增学生报告页的弱项前三区块，并在学生页头增加复习与报告入口。页面覆盖加载、空、正常、出错四态；没有学习记录时显示"还没有学习记录"，不显示 0。
- **不在本次范围**：练习出题与难度升降、练习页；班级报告与按考试视图；掌握度、最近五次分数、待复习数；知识点页 UI；AI 工具；把错题来源扩展为练习/复习。

## Capabilities

### New Capabilities

- `review`: 复习任务的自动入队、级别与间隔、到期列表、复习作答与出队，以及学生/管理员可见范围。
- `knowledge-map`: 两层知识点、别名、题目关联与合并规则，作为弱项统计的归类基础。
- `reporting`: 学生弱项前三的错误率口径、排序、样本门槛与无数据状态。

### Modified Capabilities

- `access-control`: 知识点词典按共享对象处理——老师可以建、改、合并任意知识点，不受"只能改自己建的"限制；题目与知识点的挂载仍只允许操作自己创建的题（管理员不受限）。

## Impact

- **后端**：`backend/app/models.py` 新增复习任务、知识点、别名、题目关联四张表，并补一条 Alembic 迁移；新增复习、知识点、弱项统计的模块与路由；判分完成后在同一事务内入队，入队失败则整次判分按现有规则回滚到"已交卷 + 空分"。
- **前端**：`frontend/src/api.js` 增加复习、知识点、弱项接口；`App.jsx` 增加 `/student/review` 与 `/student/report` 路由；新增两个学生页面并在学生页头加入口。
- **数据**：`chemai.db` 需要迁移；现有题目、卷子、作答与分数不改，迁移会为历史错题回填复习任务。知识点为空时弱项列表为空，不影响考试与错题功能。
- **接口契约**：继续使用 `{success, data, error}` 信封；只新增接口，不修改现有接口的字段和语义。到期日按固定 UTC+8 的业务日期计算，时间戳仍按 UTC 存。
- **依赖**：不新增第三方依赖。
