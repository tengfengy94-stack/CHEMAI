# 05 页面与选型

---

## 一、这个模块解决什么问题

前面几份设计讲的是数据怎么流、规则怎么判。用户第一次打开系统，看到的不是这些，是九个屏幕。

页面这一层最容易被做坏，因为它是唯一"看起来做完了"的一层：

| 做坏了会怎样 | 后果 |
|---|---|
| 页面按功能切得太碎 | 老师找"发布"要找三个页面，最后回到微信群问 |
| 一页塞三个主操作 | 每个都做了一半，每个都不好用 |
| 空数据直接白屏 | 新班级、新学生第一次打开就以为系统坏了 |

这个模块定九页各做什么、每页有哪几种状态、页面之间怎么走，以及用什么技术搭。

它不定业务规则。页面上显示的每个状态、每个数字，都来自前面四份设计；页面只负责把它们摆对位置。

---

## 二、核心概念与它们的关系

**一页不是一个功能，是一个角色在某个时刻要做的一件事。**

所以每页只有三样东西：谁进来、这个角色要做的那一件事、这件事有哪几种状态。超过一个主操作的，拆页；一个页面装不下的，说明还没想清楚。

九页分三组：

```
老师专用   题库    组卷    知识点    班级报告
学生专用   考试    复习    练习
两种共用   报告    对话
```

**共用页靠身份决定看到谁的数据。** 报告页学生进来是自己的，老师从班级页点进来是本班某个学生的；对话页学生问自己的学习，老师问班级。同一个页面，同一套组件，数据范围由身份卡住。

**页面状态比页面功能更重要。** 每页至少有四种状态：加载中、空、正常、出错。列表页再加"筛选后为空"，提交类页面再加"提交中、成功、失败"。不做这几种状态，页面在演示时好看，在真实数据下就露馅。

**路由按角色分组。** 老师进 `/teacher/…`，学生进 `/student/…`。共用页沿用学生的路径，老师从自己的页面点进去，不直接输网址。

## 三、正常流程：谁在什么时候做什么

老师的一条线：

```
登录
 ├→ 题库 ─→ 组卷 ─→ 发布 ─→ 班级报告 ─→ 学生报告
 ├→ 知识点
 └→ 对话
```

学生的一条线：

```
登录
 ├→ 考试 ─→ 作答 ─→ 结果 ─→ 错题 ─→ 复习
 ├→ 练习
 ├→ 报告
 └→ 对话
```

一次组卷和一次讲评的实际点击：

| 时间 | 谁 | 点了什么 | 页面上看到什么 |
|---|---|---|---|
| 周五 21:10 | 老师 | 进题库 | 十二道草稿，状态标签是灰色 |
| 周五 21:20 | 老师 | 逐道点"通过" | 标签变绿，行不再可编辑 |
| 周五 21:25 | 老师 | 进组卷，新建一份卷 | 左边题目池只剩已通过的题 |
| 周五 21:35 | 老师 | 加完十二题，点发布 | 对话框列出自己带的两个班 |
| 周五 21:36 | 老师 | 确认发布 | 卷子标签变"已发布"，加题按钮消失 |
| 周一 08:40 | 学生 | 进考试，点开始 | 卷子打开，顶部显示"已答 11/12" |
| 周一 08:55 | 学生 | 点交卷 | 确认框写"还有 1 题没答，确定交卷？" |
| 周一 08:55 | 学生 | 确认 | 跳到结果态，顶部 91.7 |
| 周一 09:10 | 老师 | 进班级报告，选这次考试 | 已交卷 52/60、作答中 3、还没开始 5；下面是逐题正确率 |

## 四、规则与判定

### 4.1 九页各做什么

| # | 页面 | 路由 | 角色 | 主操作 | 关键状态 |
|:--:|---|---|---|---|---|
| 1 | 题库 | `/teacher/questions` | 老师 | 建题、审核 | 列表、筛选后为空、建题抽屉、编辑抽屉、删除确认 |
| 2 | 组卷 | `/teacher/exams` | 老师 | 组卷、发布 | 卷子列表、编辑一份卷、发布对话框、已发布只读 |
| 3 | 知识点 | `/teacher/knowledge` | 老师 | 合并 | 树、节点详情、合并对话框 |
| 4 | 班级报告 | `/teacher/class` | 老师 | 看班级、看某次考试、下钻 | 按考试、按知识点、还没有考试记录 |
| 5 | 考试 | `/student/exams` | 学生 | 作答、交卷 | 待考列表、作答中、结果、判分没完成 |
| 6 | 复习 | `/student/review` | 学生 | 复习一题 | 今日到期、全部错题、答题、判分结果、今天没有到期的 |
| 7 | 练习 | `/student/practice` | 学生 | 练一题 | 加载下一题、答题、判分反馈、暂无题、按对话带来的题单出题 |
| 8 | 报告 | `/student/report` | 学生、老师 | 看报告 | 有数据、还没有学习记录 |
| 9 | 对话 | `/student/chat` | 学生、老师 | 提问 | 空对话、发送中、流式回答、出错 |

登录页不在九页之内，它属于身份认证，第 03 章做完就不再改。

### 4.2 关键页面的细节

**题库页**：顶部一条筛选，难度、审核状态、关键词三样；中间一张表，五列，状态用彩色标签；右上角一个"新建题目"。建题和编辑用同一个抽屉，字段相同。删除按钮一直在，点下去先查这道题有没有被卷子用过：没被用过就弹确认，被用过就直接告诉老师"已被几份卷子使用"，不弹确认——确认了也删不掉，只会让人以为自己点错了。

**组卷页**：左边题目池，右边已选，中间一个"加进卷子"。题目池只列已通过的题，可以按难度和关键词筛。题的顺序就是加进来的顺序，不做拖动。卷子建好后名字固定，草稿状态可以加减题；发布前可以按学生视角预览整份卷：题干、选项、题号，不带答案。点发布弹对话框选班级，确认框里写明发给哪个班、多少人；发布之后整页变成只读，加题、减题、发布三个按钮都消失，不是点了才报错。已发布的卷子留一个"看结果"入口，进班级页的按考试视图。

**考试页**：一页三态。列表态显示自己的所有作答记录，一条一行，带状态标签；作答态一题一块，顶部显示"已答几道 / 共几道"；结果态显示总分和逐题对错，错题旁边一个"看错题"入口，跳到复习页的"全部错题"页签。交卷时如果还有题没答，确认框要写明"还有几题没答"；交白卷要再确认一次。判分没完成时，结果态显示"答案已收，判分没完成"和一个重试按钮；重试只重跑判分，不重收答案。

**复习页**：顶部两个页签。"今日到期"是默认，按到期时间排；"全部错题"按最近一次答错倒序，可以按来源筛，也可以只看还在复习队列里的。点一道进答题态，答完回列表。今天没有到期的，给一句"今天没有要复习的"，不显示空白页。

**练习页**：默认按弱项和难度出下一题，顶部三格显示当前难度。从对话里点"去练"进来时，按对话给的那组题依次出，答完或离开就失效，不长期保存。

**班级报告页**：顶部先选一次考试。这一屏给提交情况（已交卷、作答中、还没开始）和逐题正确率——谁没交、哪道题错得多，是讲评课的入口。往下才是按知识点的弱项分布和学生表，点学生名进这个学生的报告。

**对话页**：消息列表加输入框。发送中禁用输入框，流式回答逐字追加；工具调用显示成一条浅色提示，比如"正在查你的学习情况"，不显示参数；流结束时恢复输入框。学生从练习页、错题页点"问一句"进来时，场景跟着入口走。老师进来看到的是同一页，但工具少了，只能问班级和题目。

### 4.3 每页都要有的四种状态

| 状态 | 什么时候 | 页面上是什么 |
|---|---|---|
| 加载中 | 请求还没回来 | 骨架或转圈，不留白 |
| 空 | 请求成功但没数据 | 一句说明加一个下一步按钮 |
| 正常 | 有数据 | 列表、表格或图 |
| 出错 | 请求失败 | 一句"加载失败"加重试按钮，不显示原始报错 |

**空态要说出原因。** "还没有学习记录"比"暂无数据"有用，"该知识点暂无题"比空白有用。空态还要给下一步：新学生没弱项，就给一个"先做几道题"的按钮。

**提交类动作另有三种状态**：提交中、成功、失败。提交中把按钮禁用，防止连点；失败保留用户填过的内容，不清空。

### 4.4 状态标签与文案

三个对象的状态标签，写法固定，颜色固定：

| 对象 | 标签 | 颜色 |
|---|---|---|
| 题目 | 草稿、待复核、已通过 | 灰、橙、绿 |
| 卷子 | 草稿、已发布 | 灰、绿 |
| 作答 | 待作答、作答中、已交卷、已判分 | 灰、蓝、橙、绿 |

同一套颜色只表达一件事：灰是"还没开始"，蓝是"正在进行"，橙是"等你处理"，绿是"结束了"。别的含义一律不用这四个颜色。

**数字的写法统一**：分数一位小数，满分写 100.0；错误率、掌握度按百分比，一位小数；日期显示本地时间，到期日写"今天""明天""几月几日"，不显示时间戳。

**提示文案要说下一步。** "已发布的卷子不能修改"后面跟一句"要改请新建一份"；"该班还没有学生"后面跟一句"先在班级里加学生"。只说"操作失败"的提示，等于没提示。

### 4.5 危险动作要二次确认

| 动作 | 确认什么 |
|---|---|
| 删题 | 这道题将被删除，且不能恢复 |
| 交卷 | 还有几题没答 |
| 交白卷 | 一道都没答，确定交卷 |
| 发布 | 发给哪个班，多少人会收到 |

确认框里写清楚"会发生什么"，不写"确定吗"。发布确认要显示人数——老师最怕的是发错班，人数是最后一个能拦住老师的数字。

### 4.6 共用页面的数据范围

**报告页**：学生打开是自己的；老师从班级页点学生名进来，带学生编号，只能看本班学生。老师在别班学生的报告上，看到的应该是拒绝，不是空页面。

**对话页**：学生进来只能问自己的数据；老师进来只能问自己带的班。同一页，工具不一样：学生有画像、讲错题、复习、练习；老师只有搜题、知识点、知识地图、考试结果、班级概况。

**共用不是共用数据。** 页面组件复用，身份判断在服务端做。前端传什么编号都没用，服务端按当前身份再过滤一次。

### 4.7 技术栈

| 层 | 选择 | 为什么 |
|---|---|---|
| 前端框架 | React + Vite | 组件化，启动快，改一个页面不用等打包 |
| 组件库 | antd 默认主题 | 表格、表单、对话框、标签都有，不自己做设计系统 |
| 路由 | react-router | 九个路由按角色分组，共用页带参数 |
| 图表 | Recharts | 只有两张图，折线和柱状，够用 |
| 后端 | FastAPI + Pydantic | 参数校验和接口文档一起有 |
| 数据库 | SQLite | 单文件、零安装，拷走就能跑 |
| 数据访问 | SQLAlchemy + Alembic | 建表和改表分开，改错了能回滚 |
| 认证 | PyJWT + pwdlib | 短期凭证加长期凭证，密码用 Argon2 |
| Agent | LangChain + LangGraph | 单智能体，工具循环内置 |
| 运行环境 | Node 20.19 以上、Python 3.12 | 版本由依赖文件锁定，正文不重复写 |

整套只用一个语言栈加一个前端栈，不加消息队列、不加缓存、不加容器。**能在一台笔记本上各用一条命令启动前后端，是这一版的硬要求。**

## 五、边界与异常

| 谁 | 情况 | 页面怎么反应 |
|---|---|---|
| 未登录 | 打开任何页 | 跳登录，登录后回到原来那一页 |
| 学生 | 打开老师页 | 拒绝，回自己的考试列表 |
| 老师 | 打开学生考试页 | 拒绝，回班级报告 |
| 老师 | 打开别班学生的报告 | 拒绝，不显示空页面 |
| 任何人 | 接口失败 | 显示"加载失败"和重试按钮，不白屏 |
| 任何人 | 列表为空 | 说明原因，给一个下一步按钮 |
| 任何人 | 列表很长 | 分页，每页二十条；不一次性拉全表 |
| 学生 | 刷新作答页 | 回到考试列表，状态仍是作答中；填过的答案不保留 |
| 学生 | 交卷时还有题没答 | 确认框写明还有几题 |
| 学生 | 交卷后判分没完成 | 结果态显示"答案已收，判分没完成"和重试按钮，不显示 0 分 |
| 学生 | 连点交卷 | 按钮禁用，只发一次请求 |
| 学生 | 报告没有数据 | "还没有学习记录"，不画空图 |
| 老师 | 班级还没考过试 | "还没有考试记录"，柱状图不画 |
| 老师 | 删一道被用过的题 | 提示已被几份卷子使用，不弹确认 |
| 老师 | 打开已发布的卷子 | 只读，操作按钮消失 |
| 学生 | 对话时断网 | 保留已经收到的文字，给重试 |
| 任何人 | 登录凭证过期 | 自动换一次；换不到回登录页 |

**刷新作答页是这一版最容易被投诉的地方。** 答案只在交卷时提交，刷新就没了，所以页面上要提前说清楚：作答页顶部写一行"答案在交卷时统一提交，请不要刷新"。这一版不做草稿保存。

**按钮该消失就消失，不要点了才报错。** 已发布的卷子、已判分的卷子、没权限的入口，都应该是看不见或不可点，而不是点了弹一句"不允许"。错误提示留给真正意外的情况。

## 六、与其他模块的接口

| 我依赖谁 | 依赖什么 |
|---|---|
| 数据与权限 | 当前身份、角色、能看哪些数据 |
| 题库与考试 | 题目、卷子、作答、判分结果 |
| 复习与报告 | 弱项、掌握度、复习清单、练习选题、知识点 |
| Agent | 对话流、工具事件、历史消息 |

| 我提供给谁 | 提供什么 |
|---|---|
| 用户 | 一个能自己判断"做对了没有"的界面 |
| 每一章 | 检查点里"你要看到"的那几条，都落在页面上 |

**页面不定义规则。** 状态能不能变、按钮能不能点、数字怎么算，都由前面的模块决定。页面上发现规则不对，改的是设计，不是把页面绕过去。

**页面是验收的最后一公里。** 接口通了、测试绿了，用户仍然只信自己眼睛看到的。所以页面的验收标准写成"你要看到什么"，而不是"接口返回什么"。

## 七、取舍

| 放弃了什么 | 为什么 |
|---|---|
| 自建设计系统 | 用 antd 默认主题。一套设计系统要维护颜色、间距、组件、文档，与教学闭环无关 |
| 移动端专属适配 | 按桌面浏览器做。学生用手机也能打开，但不为窄屏重排页面、不做手势 |
| 暗色主题与多语言 | 只有一种主题、一种语言。多一套主题就多一套截图和验收 |
| 富文本与公式编辑器 | 题干按纯文本存。公式编辑器要处理输入、渲染、粘贴、导出，牵一发动全身 |
| 拖动排序 | 卷内顺序就是加题顺序。拖拽要维护顺序字段和一套拖拽组件 |
| 作答草稿自动保存 | 答案交卷时一次提交。自动保存要多一个接口、多一套冲突处理 |
| 打印与导出试卷 | 卷子只在屏幕上用。导出要排版、分页、处理图片，是另一个产品 |
| 第二套图表库 | 只用 Recharts。两套图表库意味着两套配置和两套样式 |
| 前端全局状态库 | 页面级状态加请求就够。九个页面之间没有共享的复杂状态 |
| 服务端渲染 | 本地单机运行，不需要首屏优化和搜索引擎收录 |
| 页面级权限矩阵 | 三种角色加数据范围，四页老师、三页学生、两页共用，规则少到能背下来 |
| 建班与账号管理 | 班级和账号由初始化数据导入，界面不做增删改。一个学期的课，名单不会天天变 |
| 高并发写入 | 本地单机、一个班的规模，不做连接池和写入队列。六十个人同时点交卷，SQLite 会排队，不丢数据 |
