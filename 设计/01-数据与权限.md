# 01 数据与权限

---

## 一、这个模块解决什么问题

一个教学系统最怕三种事故，这个模块的设计就是为了堵住它们：

| 事故 | 真实后果 | 对应设计 |
|---|---|---|
| 学生把网址里的编号改一下，看到别人的成绩 | 家长投诉，数据泄露 | 学生只能看自己的 |
| 老师看到别的班的学生名单和分数 | 越权，同事关系崩 | 老师只能看自己带的班 |
| 老师删了一道题，三场考过的试全崩了 | 历史数据丢失，无法复盘 | 用过的题不许删 |

三种事故对应三条规则和一条删除约束。权限不是"加个登录"，是**每一次查询都要带上身份条件**。

---

## 二、系统要记住哪些事

系统要记住八件事，它们之间是这样连着的：

```
谁是谁 ──┬── 有哪些题 ──── 卷子装了哪些题
         │        │
         │        ├──── 每题答了什么 ──── 谁考了什么
         │        │
         │        ├──── 错题什么时候复习
         │        │
         │        └──── 知识点怎么归类
         │
         └── 谁练过哪些题
```

### 四条线

**教学线：题目 → 试卷 → 谁考了什么 → 每题答了什么。**
老师建题，把题放进卷子，把卷子发布给班级，每个学生得到一次作答。这条线是主干，其余三条都挂在它上面。

**知识线：知识点 ←→ 题目。**
一道题可以属于多个知识点，一个知识点下有多道题。弱项统计、自适应选题、AI 讲解都沿这条线走。没有它，系统只能告诉你"错了 7 道题"，不能告诉你"你电化学不行"。

**复习线：错题 → 什么时候复习 → 复习结果。**
判分产生的错题进复习队列，按间隔排到未来某天；每次复习的结果决定下一次排到哪天。这是系统里唯一带时间的线。

**身份线：谁是谁。**
所有查询都从这里取"我是谁"，再决定"我能看到什么"。

## 三、逐件事说明

### 3.1 谁是谁：用户与班级

**要记住的**：每个人的姓名、身份（老师 / 学生 / 管理员）、登录凭证、属于哪个班；每个班的名称和班主任。

**为什么需要**：没有它，所有信息都没有归属，权限无从谈起。

**谁产生**：管理员在开学时批量导入班级和账号。学生不能自己注册——教学系统里账号是学校发的。这一版不做建班、加人、改归属的界面，需要时由管理员直接改数据。

**谁使用**：每一次查询。所有过滤条件都从"我是谁"推出来。

**什么时候消失**：**不消失**。老师离职、学生转班，都是改归属或改状态，不是删人。历史成绩要挂在学生名下，人删了就成无主数据。

**一处取舍**：三种身份记在一处，不拆开。拆开的话，登录、权限、页面显示三处都要写三遍分支。代价是有些信息对某些身份永远为空（比如老师没有班级归属），换取三处逻辑各写一遍。

### 3.2 有哪些题

**要记住的**：题干、题型、选项、标准答案、解析、难度、审核状态、谁建的。

**谁产生、谁能改**：老师建，只有建的人能改。同事之间不共改一道题——要共享就复制一份。

**审核状态怎么走**：

```
草稿 ──→ 待复核 ──→ 已通过
  └──────────────────┘
```

- **草稿**：刚建好，只有自己看得见
- **待复核**：内容可能有问题，标出来但还没定
- **已通过**：学生可见，终态，通过之后不能再改

**为什么要有这个状态**：没有第二个人审，这是**给自己留的一道闸**——出完先存草稿，第二天再看一遍才放行。

**什么时候消失**：只有没被卷子用过的情况才允许消失。**一道题一旦被任何一份卷子用过，就不许删**——删了之后，考过的卷子里这道题变空白，学生的作答和历史成绩全部失准。系统要拦住这个动作，并告诉老师"这道题已被几份卷子用过"。

### 3.3 卷子装了哪些题

**要记住的**：卷子叫什么、谁建的、什么状态、装了哪些题、题的顺序。

**谁产生**：老师。

**状态只有两种**：草稿、已发布。

**为什么已发布就锁定**：发布意味着学生已经拿到卷子。此时改题，先交卷的和后交卷的做的不是同一份卷，分数不可比。要改就新建一份重新发布。

**一处取舍**：这套设计里"题库"和"试卷"是同一件事。老师嘴里的题库其实就是一叠卷子；分开做会让"新建题库"和"新建试卷"变成两个几乎一样的动作，老师会问"我该建哪个"。

### 3.4 谁考了什么

**要记住的**：某个学生某次考试这件事——考的是哪份卷、发给了哪个班、什么时候发的、交没交、多少分、什么时候判完的。

**谁产生**：**发布时系统自动产生**，不是学生点出来的。老师发布给一个班，班上每个学生各得一份待考。

**状态怎么走**：

```
待作答 ──→ 作答中 ──→ 已交卷 ──→ 已判分
```

- **待作答**：卷子发下来了，还没点开始
- **作答中**：学生点了开始。这一步必须有，否则分不清"没开始"和"开始了但没交"
- **已交卷**：答案收上来了，分还没算
- **已判分**：分算完，终态

**为什么按学生记，不按考试记**：按考试记的话，"谁交了谁没交"要再关联一层才能看出来。按学生记，状态和分数就归在自己名下，一眼能看。

**一处边界**：同一份卷子对同一个学生只能有一份。重复发布给同一个班时，已经有的跳过，不重复发——否则一个学生会收到两份一样的卷子。

**为什么要记住发给哪个班**：学生后来转班，那次发布的名单和班级统计都不能变。统计的是"当时那个班考得怎么样"，不是"现在这个班里有谁"。转班改写历史，一次考试的数字就会在事后悄悄变掉。

### 3.5 每题答了什么

**要记住的**：这次考试里，每道题学生答了什么、对错、得了几分。

**谁产生**：学生交卷时，系统按提交的答案逐题写下。

**一处边界**：**没作答的题也要记一条空的**。不记的话，"这道题学生没答"和"这道题不存在"分不清，判分漏题也无从发现。

### 3.6 错题什么时候复习

**要记住的**：哪个学生对哪道题、复习到第几级、下次什么时候、上次答的是什么、对还是错。

**谁产生**：判分完成时，系统自动给每道错题记一条。学生也可以让 AI 手动加一条。

**怎么变**：一个学生对一道题只有一条。答对升级、答错归零，级别到顶移出队列。**移出不是删除**——留着，只是不再出现在"今日到期"里。删了就无法回答"这道题我复习过几次"。

**一处边界**：学生后来又考错同一道题，要回到最低级，不是新加一条。

**为什么记住上次答的是什么**：错题本要显示"最近一次答错的答案"。考试和练习的答案在作答记录里，复习答错的答案只在这条任务上——不记，复习里错过的题就显示不出当时答了什么。

### 3.7 知识点怎么归类

**要记住的**：知识点叫什么、有哪些别名、上级是谁；每道题属于哪些知识点、主次如何。

**谁产生**：老师。可以手动建，也可以把两个近义节点合并成一个。

**合并会发生什么**：源节点的别名、题目归属、下属节点全部并入目标，源节点消失。**合并不是删除，是改正**——之前统计错在把同一个知识点算成了两个。

**合并要检查方向**：目标不能是自己，也不能是自己的下级。把上级并进下级，子节点改挂时会转出一个环，树就坏了。这种合并要拒绝，不能让它悄悄写进去。

**一处边界**：合并之后，历史统计要按合并后的节点重新算。旧节点的数据不保留，因为旧节点本身就是个错误。

**一处取舍**：知识点有层级（氧化还原 → 氧化剂 / 还原剂），但只做两层。三级以上对"找出弱项"没有额外价值。

### 3.8 谁练过哪些题

**要记住的**：哪个学生练过哪道题、当时给的难度、对还是错、什么时候。

**为什么要记"当时给的难度"**：题目本身的难度是固定的，但"这次算难还是算易"是相对的。不记下来，事后无法还原当时为什么升难度或降难度。

## 四、业务上只有这几种情况

设计要定的是**一件事在业务上有几种结局**，不是这些结局在代码里怎么拼写。代码里的拼写由第一次用到它的那一章定下来，之后沿用。

**身份**：老师、学生、管理员。只有三种，没有访客、没有家长。

**题目形态**：单选、多选、填空。只有三种。

**题目审核**：草稿（自己看得见）、待复核（标出来但没定）、已通过（学生可见）。已通过是终态。

**试卷**：草稿（可以改）、已发布（锁定）。

**作答**：待作答、作答中、已交卷、已判分。四个状态对应四件事：卷子发了、学生开始了、答案收上来了、分算完了。

**复习级别**：最低到最高共六级。到最高级就移出队列。

**难度**：三档。五档听起来细，但老师出题时说不清"中等偏难"到底差在哪；三档足够支撑"给弱项学生出简单一点的题"这一个用途。

**角色身份只在前端翻译成中文显示**。代码里统一用英文标识，避免中文值在比较和排序时出问题。

## 五、答案怎么记

选择题的选项按 A、B、C 顺序列出，每个选项一个字母加一段文字。

答案按题型记：

| 题型 | 怎么记 | 例子 |
|------|--------|------|
| 单选 | 一个字母 | A |
| 多选 | 字母连写、升序、不隔开 | AC |
| 填空 | 原文 | NaCl |

知识点的别名按一串文字记，用于把"氧化还原"和"氧化还原反应"归到一起。

**为什么必须统一**：判分、练习、复习三处读的是同一份答案。三处各写一套，就会出现"考试判对了、复习判错了"这种查不出来的错。

## 六、权限

### 6.1 三种角色

| 角色 | 能做什么 |
|---|---|
| 老师 | 建题、审题、组卷、发布、看自己班的学情 |
| 学生 | 作答、复习、练习、看自己的报告、用 AI 助教 |
| 管理员 | 全通，只用于造数据和排障 |

### 6.2 三条规则

**只能改自己建的**。同事之间不共改一道题。要共享就复制一份，不要共用一个对象。

**只能看自己的**。改网址里的编号是最常见的越权方式。凡是按学生查的东西，都要先确认"要查的这个学生就是你自己"。

**只能看自己带的班**。班级是老师之间的边界，跨班看分数在学校里是敏感行为。

### 6.3 边界场景

规则不能只写"正常情况下能做什么"，要写清楚这些情况怎么办：

| 谁 | 想做什么 | 系统应该怎么反应 |
|---|---|---|
| 学生 | 把网址里的编号改成别人的 | 拒绝，不返回任何数据 |
| 学生 | 用别人的账号登录 | 不允许，登录凭证只对本人有效 |
| 老师 | 改同事出的题 | 拒绝，提示"不是这道题的创建者" |
| 老师 | 删已被卷子用过的题 | 拒绝，提示"已被几份卷子用过" |
| 老师 | 看别班的学生名单 | 拒绝 |
| 老师 | 改已发布卷子里的题 | 拒绝，提示"已发布的卷子不能修改" |
| 管理员 | 造数据、看全部 | 允许 |

### 6.4 规则落在三层

权限不是一处能挡住的，分三层各管一段：

| 层 | 管什么 | 挡不住什么 |
|---|---|---|
| 登录校验 | 有没有带有效凭证 | 带了凭证但越权 |
| 归属判断 | 这条数据是不是你的 | 你的数据里混进了别人的 |
| 查询过滤 | 列表类只看得到范围内的 | 单条查询忘了加过滤 |

三层都要有。最常见的事故是"列表页过滤了、详情页忘了"。

### 6.5 为什么不做权限矩阵

不做权限矩阵。矩阵是一张表，出错时你只知道"某处不对"，不知道是哪一行动作写错了。

三条规则是三个真实场景，每个都能写出一条"应该被拒绝"的用例。所以这里用**六条越权用例**代替矩阵：老师改别人的题、学生读别人的卷、学生改别人的答案、老师看别班、无凭证访问、伪造凭证。这六条跑通，比一张矩阵更有说服力。

## 七、与其他模块的接口

| 我提供给谁 | 提供什么 |
|---|---|
| 题库与考试 | 题目、卷子、作答的归属规则 |
| 复习与报告 | 知识点归属、作答记录、班级范围 |
| Agent | 当前用户是谁、能看哪些数据 |

| 我依赖谁 | 依赖什么 |
|---|---|
| 无 | 它是地基，不依赖任何其他模块 |

## 八、取舍

| 放弃了什么 | 为什么 |
|---|---|
| 家长与亲子绑定 | 需要独立一套登录和可见性规则，与核心闭环无关 |
| 教师入驻审批 | 账号由管理员造，不需要审批流 |
| 软删除 | 只在"没被用过"时允许删题，其余一律不删。软删除会让每个查询都要加"未删除"条件，很容易漏 |
| 多学校隔离 | 只有一个学校、一个学科，不做学校级数据隔离 |
| 知识点无限层级 | 只做两层，够支撑"找出弱项"，不做知识图谱推理 |
