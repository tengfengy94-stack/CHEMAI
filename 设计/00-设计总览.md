# 00 设计总览

---

## 一、这个系统解决什么问题

一个化学老师带两三个班，每天要做的事是重复的：出题、组卷、判卷、讲错题、盯谁掉队、给跟不上的学生补练。

系统只做三件事：

1. **把出题和组卷变成一次点击能复用的资产**。同一道题今年给这个班用，明年给另一个班用；历年真题不用再翻文件夹。
2. **把判分和错题变成自动的**。客观题不用手改，错题自动进册，不用老师拿红笔一道一道记。
3. **把"这个学生哪里不行"从经验判断变成可查的数据**。老师凭印象说"这学生氧化还原不行"，系统给出错误率、错误次数、最近趋势。

AI 助教是第四件事，但它是附加的：前三件事没有 AI 也能跑，AI 让"问一句就能得到答案"成为可能。

**三个角色，三种用法：**

| 角色 | 每天打开系统做什么 | 一次典型使用 |
|---|---|---|
| 老师 | 建题、审题、组卷、发布、看班级情况、问 AI | 周五晚上花 20 分钟组一套周测卷，发布给两个班 |
| 学生 | 做题、看分、复习错题、问 AI | 考完看哪几道错了，问 AI"这道为什么错" |
| 管理员 | 造种子数据、排障 | 新班级建好，导一批老师和学生账号 |

## 二、五个模块与它们的边界

```
                    ┌──────────────┐
                    │  数据与权限   │  ← 地基：谁是谁、谁能碰什么
                    └──────┬───────┘
                           │
              ┌────────────┴────────────┐
              ↓                         ↓
      ┌──────────────┐          ┌──────────────┐
      │  题库与考试   │          │  复习与报告   │
      └──────┬───────┘          └──────┬───────┘
             │     考试产生错题          ↑
             └─────────────────────────┘
                           │
                    ┌──────┴───────┐
                    │    Agent     │  ← 消费上面全部数据
                    └──────────────┘
```

| 模块 | 负责 | 不负责 |
|---|---|---|
| 数据与权限 | 要记住哪些事、它们的关系、业务词表、三条权限规则 | 业务流转、页面呈现 |
| 题库与考试 | 题目从建到审、卷子从组到发、作答与判分 | 复习安排、学情分析 |
| 复习与报告 | 错题怎么排复习、练习难度怎么调、数据怎么汇总 | 题目质量、考试流程 |
| Agent | 对话、工具调用、上下文、人设、护栏、评测 | 业务规则本身（它只调用） |
| 页面与选型 | 九页的职责、状态、流转，技术栈 | 业务逻辑 |

**单向依赖**：箭头只往下。题库不依赖复习，复习不依赖 Agent，Agent 依赖全部。反过来的依赖一律视为设计错误。

## 三、全局约定

**术语**：文档里的"题"指一道题目，"卷"指一份试卷，"作答记录"指某个学生的一次考试。三者不混用。角色只三种：老师、学生、管理员。

**语言**：枚举值在代码里用英文码，界面显示中文。设计文档只写中文，代码里的拼写由第一次用到它的那一章定下来，之后沿用。

**时间**：统一按 UTC 存，只在显示时转本地。这条不是技术偏好——第 07 章要算"明天到期"，如果不统一时区，跨零点会算错一天。

**范围外**：家长端、OCR 批改、通知推送、预警定时任务、多智能体、向量检索、线上部署。这些不是"以后再说"，是**这一版明确不做**——它们各自都完整，但都不在"出题→考试→判分→复习"这条主链上。
