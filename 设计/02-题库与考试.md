# 02 题库与考试

---

## 一、这个模块解决什么问题

周五晚上八点，老师要给两个班出一套周测。手上有三十几道题，散在旧卷子、教案本和聊天记录里。要挑十二道，排好顺序，发给两个班；周一收上来，判六十份卷，把错得多的题记下来，下节课讲。

这条链上有四个地方会出事：

| 会出的错 | 后果 |
|---|---|
| 题没写完就发下去 | 学生做到一道半成品，家长截图问"这题是不是少印了一个条件" |
| 卷子发下去还在改 | 先交卷的和后交卷的做的不是同一份卷，分数不可比 |
| 学生交了两次 | 第二次覆盖第一次，学生自己也说不清哪份算数 |
| 判分靠人 | 六十份卷判到半夜；多选漏选算不算对，每次标准都不同 |

这个模块只做一件事：**让这条链从头到尾不需要老师手工兜底**。题建好、审过才发；卷子发出去就锁死；交一次只收一次；判分按写死的规则算，谁算都一样。

省下的不是出题时间，是周一的判卷时间，和讲评时翻卷子的时间。一道题今年给这个班用，明年换个班还能用——题目是资产，不是一次性的耗材。

模块边界：
- 管：题目的增、改、审、删，卷子的组装与发布，作答的收与判，错题的列。
- 不管：错题怎么排复习、哪个知识点是弱项、AI 怎么讲这道题。这三件事分别由复习与报告、Agent 接手。

## 二、核心概念与它们的关系

这五个概念里，前两个由老师造，后三个跟着考试这件事自动长出来：发布时生作答记录，交卷时生逐题作答，判分时挑出错题。

```
题目 ──装进──→ 卷子 ──发给一个班──→ 作答记录（每人一条）
                                        │
                                     交卷判分
                                        ↓
                                逐题作答（每题一条）
                                        │
                                   答错的挑出来
                                        ↓
                                      错题
```

| 概念 | 谁产生 | 什么时候 | 之后会不会变 |
|---|---|---|---|
| 题目 | 老师 | 备课的时候，一次一道 | 草稿和待复核能改，已通过不能改 |
| 卷子 | 老师 | 考前，一次一份 | 发布前能加题减题，发布后只读 |
| 作答记录 | 系统 | 老师点发布的那一刻，班上每人一条 | 状态随学生动作往前走，分数判完才写 |
| 逐题作答 | 系统 | 学生交卷时，卷子里每道题一条 | 写完不再变 |
| 错题 | 系统 | 判分时从逐题作答里挑出答错的 | 答对不会移走，移出是复习队列的事 |

**系统里没有"考试"这个对象。** 一次发布就是把一份卷子发给一个班，每个学生各得一条作答记录。老师嘴里的"这次考试"，在系统里是"这份卷子在这个班的这批作答记录"。这么定是因为同一份卷子给两个班用是常事：如果按"考试"记，同一份卷子要建两次，题还要再录一遍。

**错题不是一份新记录。** 它是逐题作答里答错的那部分，一次查询就能列出来。不单独存一份，是因为对错在判分时已经写下了，再存一份就有两处会不一致。

**题目和卷子是一对多，卷子和作答记录是一对多。** 一道题可以进很多份卷子，一份卷子可以发很多次，但一个学生对同一份卷子只有一条作答记录。这条约束贯穿整个模块，下面的规则大半是在守它。

**没有单独的"成绩"这个东西。** 分数就写在那条作答记录上。一次作答只有一个总分，拆成一张成绩表，每次查分都要再关联一次；逐题对错本来就在逐题作答里，也不需要另存一份。少一个对象，就少一处会对不上的地方。

## 三、正常流程：谁在什么时候做什么

| 步骤 | 谁 | 做了什么 | 系统里发生了什么 | 学生看到什么 |
|:--:|---|---|---|---|
| 1 | 老师 | 建题 | 存成草稿，只有自己看得见 | 看不到 |
| 2 | 老师 | 审题 | 标待复核，或直接通过 | 通过之后才可能看到 |
| 3 | 老师 | 组卷 | 从已通过的题里挑，加进卷子 | 看不到 |
| 4 | 老师 | 发布 | 卷子锁定，给班上每人建一条待作答 | 列表里出现一份待考试卷 |
| 5 | 学生 | 点开始 | 记录从待作答变作答中 | 卷子打开，可以填 |
| 6 | 学生 | 交卷 | 答案逐题收下，未答的记空，状态变已交卷 | 提交后不能改 |
| 7 | 系统 | 判分 | 同一次请求里逐题比对，写对错和总分，状态变已判分 | 结果页出现分数 |
| 8 | 学生、老师 | 看结果 | 学生看自己的逐题对错，老师看这份卷子全班的 | 错题进错题列表 |

第 6 步和第 7 步是同一次请求。学生点"交卷"，服务端收答案、判分、改状态一次做完；从学生的角度看，点完就出分。

一次周测的实际节奏：

| 时间 | 谁 | 做了什么 | 系统里发生了什么 |
|---|---|---|---|
| 周五 20:10 | 老师 | 建十二道题 | 十二条草稿，只有老师自己看得见 |
| 周五 21:00 | 老师 | 逐道点通过 | 十二道变成已通过，可以发给学生了 |
| 周五 21:20 | 老师 | 组卷 | 一份草稿卷，装了十二道题 |
| 周五 21:30 | 老师 | 发布给两个班 | 卷子锁定，六十个学生各一条待作答 |
| 周一 08:00 | 学生 | 点开始 | 自己的记录变作答中 |
| 周一 08:40 | 学生 | 交卷 | 逐题作答写下，判分，出分 |
| 周一 09:00 | 老师 | 看这份卷子的全班结果 | 谁几分、哪道题错得多 |

题目从老师的世界进入学生的世界，只有两个动作：审题通过、发布。其余动作都在这条链上往前推，不改题目的可见范围。判分之后放开的是答案的可见范围，那是另一回事。

三个对象的流转：

```
题目      草稿 ──→ 待复核 ──→ 已通过
            └────────────────→ 已通过

卷子      草稿 ──→ 已发布

作答      待作答 ──→ 作答中 ──→ 已交卷 ──→ 已判分
```

谁触发：草稿到待复核或已通过，老师；草稿到已发布，老师；待作答到作答中、作答中到已交卷，学生；已交卷到已判分，系统。

## 四、规则与判定

### 4.1 一道题长什么样

三种题型：单选、多选、填空。选择才有选项，填空没有选项。填空题只有一个空。

一道题要记住：题干、题型、选项、标准答案、解析、难度、审核状态、建题的人。

选项有几个列几个，从 A 开始往后编号；标准答案必须是选项里有的字母。难度分三档，建题时老师自己选，系统不自动算。解析可以不填，不填时学生看到"暂无解析"。题干、选项、解析都按纯文本录入，不接公式编辑器，页面按原文显示。

题干里不能带图。装置图、结构式、流程图这一版都放不进来，只收纯文字的题。化学题里配图很常见，组卷时老师会撞上这条限制，只能换一道题。

答案只有三种写法，全课统一：

| 题型 | 写法 | 例子 |
|---|---|---|
| 单选 | 一个字母 | A |
| 多选 | 字母连写，升序，不隔开 | AC |
| 填空 | 原文 | NaCl |

**标准答案在保存时就写成这三种形式之一。** 老师输入"C,A"或"ac"，存进去的是"AC"。等到判分再清洗，存下来的就是一个不规范的答案，页面上显示也乱。

判分、练习、复习三处读的是同一份答案。三处各写一套，就会出现"考试判对了、复习判错了"这种查不出来的错。

### 4.2 题目的三种状态

| 状态 | 谁能看见 | 能不能改 |
|---|---|---|
| 草稿 | 只有建题的人 | 能 |
| 待复核 | 只有建题的人 | 能 |
| 已通过 | 建题的人和全体学生 | 不能 |

草稿可以直接通过，也可以先标待复核再通过。待复核不能退回草稿。已通过是终态。

**学生能看到的题，一律是已通过的题。** 搜题、练习、进卷子，三条入口都只取已通过的。审核因此不是一道流程，是一道可见性开关：老师点下通过，这道题才进入学生的世界。

筛选和搜索守同一条：老师搜自己的题，搜到的可以是草稿；学生搜题，条件里永远多一条"已通过"。列表过滤了、搜索没过滤，是最常见的漏法。

**为什么有中间那一档**：这不是第二个人审，系统里没有教研组长。待复核是**给自己留的闸**——出完先标一下，第二天再看一遍才放行。AI 生成的题、自己拿不准的题，先扔在这里。

**为什么通过后不能改**：一道题一旦发进卷子，它就成了历史的一部分。改一个字的后果是：同一份卷子，昨天考的和今天翻到的不是同一道题，学生的错题解析也对不上了。要改就新建一道，旧的那道留在历史里。

**谁审**：只有建题的人能审自己的题。同事不能替你审，也不能改你的题；要共用，就自己再建一道。这条规则的边界由权限模块定，这里只交代业务上的后果。

### 4.3 什么题能删

只有从没进过任何卷子的题能删。进过就不能删，系统告诉老师"这道题已被几份卷子使用"。

草稿卷也算用过。判断"用过"不看卷子的状态，因为今天的草稿卷明天就会发布；按状态判断，等于留了一个"先删题再发布"的口子。

**为什么**：删了之后，考过的卷子里这道题变空白，学生的作答和历史成绩全部失准。拦这个动作，拦的是"历史数据被一个删除键改掉"。

### 4.4 组卷

**只有已通过的题能进卷子。** 组卷页的题目池里不出现草稿和待复核的题。

卷子最终要发给学生。没审过的题发下去，学生看到的是一道半成品，审核这道闸就被绕过去了。题目池直接不显示，比发布时再报错好：老师在那时候已经排好十二道题，再让老师回去补审，返工太大。

一份卷子里同一道题只出现一次。老师重复加同一道题，第二次直接忽略，不报错，也不在卷子里留两个位置。题目顺序就是加进来的顺序，这一版不做拖动排序。

卷子的名字在新建时定下，之后不改。草稿卷可以加题、减题；**已发布只读**，题也不能再动。

发布意味着学生已经拿到卷子。此时改题，先交卷的和后交卷的做的不是同一份卷，分数不可比。要改就新建一份，重新发布。

空卷不能发布，提示"卷子里还没有题"。

### 4.5 发布

发布要选一个班，只能选自己带的班。系统给这个班每个学生各建一条待作答，同时记下这次发给了哪个班。发布之后，学生在自己的列表里立刻看到这份卷子，不用等老师通知。

**一次发布绑定一个班，之后不改。** 学生后来转班，这次发布的名单和班级统计都不变。按学生现在在哪个班去归集，一次考试的数字会在转班之后悄悄变掉。

**同一份卷子对同一个学生只能有一条。** 重复发布给同一个班，已经有的跳过，只补没有的，不报错。

这里防的是一个具体事故：老师点了两次发布，一个学生收到两份一样的卷子，交了一份，另一份永远待作答，班级完成率就永远到不了 100%。

班级里没有学生时拒绝发布，提示"该班还没有学生"。

**已发布的卷子可以再发给另一个班。** 锁定锁的是卷子的内容，不是发给谁。同一份卷子给三个班用，就是一次组卷、三次发布、三批作答记录。

发布之后新转进这个班的学生，不会自动有这份卷子；老师再点一次发布，只给这个学生补一条。

### 4.6 作答

四种状态对应四件事：卷子发了、学生开始了、答案收上来了、分算完了。

必须拒绝的动作有四个：

| 动作 | 拒绝的理由 |
|---|---|
| 没点开始就交卷 | 分不清"没开始"和"开始了但没交" |
| 交了再交一次 | 第二次会覆盖第一次，分数说不清 |
| 判完分再交 | 分数已经定了，改答案等于改分 |
| 没作答就判分 | 判分是交卷的下一步，没有跳过交卷的入口 |

**唯一的例外是判分没完成。** 卷子停在"已交卷"、分数还是空的时候，再提交一次不重收答案，只重新判分。这是给判分出错留的回路：不给这条路，这张卷子会永远停在"已交卷"，学生看不到分，老师也没法收尾。已经有分数的卷子，再提交一律拒绝。

**开始作答可以点第二次。** 学生刷新页面、换个设备、关掉浏览器再回来，都会重新点"开始"。系统不能把学生挡在门外；第二次开始按继续处理，不报错。答案只在交卷时提交一次，没交之前关掉浏览器，填过的内容就没了。

**交卷只收一次。** 学生在两个窗口里同时点交卷，或者网络慢时连点两下，先到的那个算，后到的被拒绝，后到的不能覆盖先到的答案。

**作答时学生看到的是题干、题型、选项，看不到标准答案和解析。** 交卷判分后，结果页才给出全部。这一条拦的不是作弊，是误发：答案和解析是题目的一部分，但发卷时它不是给学生的。

**没作答的题也要收一条空答案。** 不记的话，"这道题学生没答"和"这道题不存在"分不清；判分漏题也无从发现。空答案按错算。

**判分之后，学生能回看整份卷子。** 每道题的题干、自己的答案、标准答案、解析、对错，都在结果页里。不是只看错题——答对的题也要能翻回去看当时怎么答的。

### 4.7 判分

| 题型 | 怎么比 |
|---|---|
| 单选 | 去掉首尾空白后完全相等 |
| 多选 | 去掉空白和分隔符、转大写、按字母升序排，再比选项集合是否完全相等；漏选、多选了都不得分 |
| 填空 | 全角转半角、去掉所有空格，再比原文；大小写敏感 |

多选比的是集合，不是字符串。"CA"和"AC"是同一个答案，"ABC"和"AB"不是。漏选还给分，等于把"不完全对"算成"对"；多选了还给分，等于把"没看出来"算成"看出来了"。两种都会让分数失去区分度。

填空统一写法，是因为手机输入法在中文状态下打出的是全角字母："ＮａＣｌ"和"NaCl"在人眼里是同一个东西。判错的话，学生丢的分跟会不会化学无关，跟用什么输入法有关。

**但大小写不能统一。** 化学里大小写是信息：CO 是一氧化碳，Co 是钴；NO 是一氧化氮，No 是锘。抹平大小写，就会把两个不同的答案判成同一个。全角转半角解决的是输入法问题，大小写是学生自己按的键，按错了就该判错。

**总分 = 正确题数 ÷ 卷子总题数 × 100，保留一位小数。**

| 卷子题数 | 答对 | 分数 |
|:--:|:--:|:--:|
| 3 | 3 | 100.0 |
| 3 | 2 | 66.7 |
| 3 | 1 | 33.3 |
| 3 | 0 | 0.0 |
| 6 | 5 | 83.3 |
| 12 | 9 | 75.0 |

分母是卷子的总题数，不是学生答了的题数。漏答的题按错算。用答了的题数当分母，少答的人反而分高。

满分也写成 100.0，不写 100。整个系统里分数只有一种显示格式。

**判分在交卷那一次请求里同步做完。** 不做后台任务，不交给 AI。学生交完卷就该看到分，异步要多一个"判分中"的中间态，还要轮询、要处理超时，比省下的几百毫秒贵。判分也不进模型：模型的"意思对了也算对"没法在两个班之间比较，也没法复核。

**判分和改状态一起成功。** 中途出错，答案留在"已交卷"，分不写，状态不往前走。系统里不允许出现"分数算了但状态没改"这种半截数据。学生那边看到的是"答案已收，判分没完成"，页面上给一个重试；重试只重跑判分。

**已交卷但没判分的卷子，分数是空的，不是 0。** 报告和统计要跳过它，不能把它当成 0 分算进平均分。这是判分这一步唯一一种停在中间的情况，读分数的每一处都要想一遍它。

### 4.8 错题

判分时，答错的题成为错题。错题清单要给出：题干、选项、学生的答案、标准答案、解析、来源。

**按题去重。** 同一道题只出现一次，显示最近一次答错时的答案和来源。一道题错了三次，错题本里列三遍没有意义。清单按最近一次答错的时间倒序，新错的排前面。

来源有三种：考试、练习、复习。复习时答错的，最近一次答案记在那条复习任务上，不在作答记录里另存一份。第 06 章只有考试一种，练习和复习在后面的章节产生。

**答对不会把题从错题本里移走。** 错题本是"我错过哪些题"的记录，不是"我现在还差哪些题"。后者是复习队列的事：一道题在复习里答对够次数，是复习队列让它出队，不是错题本被删。

错题列表的可见范围和结果一样：学生看自己的，老师看本班学生的。

### 4.9 谁能看谁的结果

学生看自己的作答记录、分数、逐题对错、错题。

老师看自己发布的卷子下面全班的作答记录、分数、逐题对错、错题。

老师看结果的范围跟着"谁发的这份卷子"走，不跟着"哪个班的题"走。同事发的卷子，即使是自己班的学生，也不在这里看——跨人看成绩是权限模块管的事。

### 4.10 一道题走完全程

一道多选，标准答案"AC"，难度 2。老师周五建成草稿，当晚点通过。组卷时它被加进周测卷，排第 5 位。

周一学生打开卷子，看到题干和 A、B、C 三个选项，看不到答案。学生选了 A 就交卷。

判分时，学生的答案是"A"，标准答案是"AC"。两边都转成集合，学生选的只是两个正确字母里的一个，这道题 0 分。整份卷子 12 道，学生对了 11 道，总分 91.7。

错题本里多了一条：这道题、学生答的 A、标准答案 AC、解析、来源是考试。同一道题以后再错，这一条只更新，不新增。

老师在班级结果里看到：这道题全班 30 个人里 12 个错，是这份卷子错得最多的一道。

## 五、边界与异常

| 谁 | 想做什么 | 系统怎么反应 |
|---|---|---|
| 老师 | 把草稿题加进卷子 | 题目池里根本没有这道题 |
| 老师 | 改已发布卷子里的题 | 拒绝，"已发布的卷子不能修改" |
| 老师 | 改一道已经通过的题 | 拒绝，"已通过的题不能修改" |
| 老师 | 删一道被卷子用过的题 | 拒绝，"已被几份卷子使用"，并给出份数 |
| 老师 | 删一道没被任何卷子用过的题 | 允许，删除前确认一次 |
| 老师 | 把同一份卷子再发给同一个班 | 跳过已有的，只补缺的，不报错 |
| 老师 | 把同一道题加进卷子两次 | 第二次忽略，卷子里只有一个位置 |
| 老师 | 发错了班 | 没有撤回入口，已发的记录留着；只能再发一份正确的 |
| 老师 | 发给一个没有学生的班 | 拒绝，"该班还没有学生" |
| 老师 | 发布一份空卷 | 拒绝，"卷子里还没有题" |
| 学生 | 没点开始就交卷 | 拒绝 |
| 学生 | 交两次 | 第二次拒绝，"已经交过了"；第一次判分没完成的除外，那种情况只重判 |
| 学生 | 交白卷 | 允许，判 0 分；页面先确认一次 |
| 学生 | 在作答页找标准答案 | 接口不下发标准答案和解析 |
| 学生 | 判分后回看卷子 | 允许，结果页给出整份卷子的题干、标准答案、解析 |
| 学生 | 打开别人的答卷 | 拒绝，不返回任何数据 |
| 学生 | 想重考一次 | 没有入口；要重考，老师新建一份卷子 |
| 学生 | 中途关掉浏览器 | 记录停在作答中，回来点开始继续；没交卷的答案不保留，要重填 |

**交白卷为什么允许**：学生生病、放弃、按错，都可能是真的。拦下来学生就永远交不了，班级完成率永远差一个人。判 0 分是事实，不是惩罚。

**发错班为什么不做撤回**：撤回要决定已发的记录是删掉还是作废。删掉，学生那边的页面上卷子会凭空消失；作废，要多一个状态，多一套"作废的卷子不算分"的规则。两条都比"再发一份正确的"贵。这一版选重新发一份，代价是那个班的学生会多看到一份不该有的卷子。

**作答中停住不动的记录不会自己消失。** 老师看到的是"作答中"，班级完成率算不满。这一版不做超时自动交卷，也不做提醒。

**同一份卷子发给两个班，两个班互不影响。** 一班考完了、二班还没开始，是正常状态：卷子只管内容，作答记录各归各的学生，老师看结果时按班分开看。

**卷子里有题被删的情况不会发生。** 题一旦进过卷子就不能删，所以已发布的卷子和历史上的作答记录永远对得上。这不是运气，是 4.3 那条规则在守。

**判分规则变了怎么办。** 判分规则是代码里写死的，不在界面上配。改规则只影响之后交的卷子，已经判过的分数不动。历史分数是事实，不因为规则改了而重算。

## 六、与其他模块的接口

| 我提供给谁 | 提供什么 |
|---|---|
| 复习与报告 | 判分结果、错题清单、每个学生的分数与作答状态、**判分规则本身** |
| Agent | 某个学生某次作答的逐题结果、错题、一份卷子全班的作答概况 |
| 页面与选型 | 五个页面要的数据：题库列表、组卷题目池、学生作答、结果页、错题列表 |

| 我依赖谁 | 依赖什么 |
|---|---|
| 数据与权限 | 题是谁建的、卷子发给哪个班、学生只能读自己的作答记录 |
| 无其他 | 不依赖复习与报告，也不依赖 Agent |

**判分规则是这一模块对外最重要的一件东西。** 复习页判一道题、练习页判一道题，用的必须是同一套比较规则。三处各写一份，就会出现"同一道题考试判错、复习判对"，这种错在页面上看不出来，只能靠对数据发现。所以判分不是题库模块的私有实现，是它对外提供的一项能力。

**错题往后的去向不在这一模块。** 判分只负责说"这道题学生答错了"；什么时候再让学生做、排到哪天、连续答对几次出队，是复习与报告的事。

**这一模块不读知识点。** 判分只认答案，不看这道题属于哪个知识点。知识点是统计和选题的事，由复习与报告与 Agent 读取。

**知识点也不在题库的规格里。** 题目只管题干、选项、答案、解析这些内容本身；它属于哪个知识点、怎么归类，是复习与报告的事。验收题库时不要把它算进来。

## 七、取舍

| 放弃了什么 | 为什么 |
|---|---|
| 主观题、多空填空 | 要人工判或按空拆答案。主链路只做机器能判的三种题型，判分才敢同步做 |
| 按题赋分 | 每题等分、百分制。赋分要配一张分值表和一套合计规则，对讲评没有帮助 |
| 人工改分与申诉 | 老师不能覆盖分数。改分要留痕、要说明理由，否则成绩就不作数了 |
| 重考与补考 | 一人一卷一条。要重考就新建一份卷子，历史记录保持原样 |
| 限时与倒计时 | 加了要处理超时自动交卷、断线续考，跟主链路无关 |
| 统一放榜 | 交卷即出分，老师不能在学生交卷后暂缓放分。真实考试常有"全班一起公布"，这一版不做 |
| 拖动排序 | 卷内顺序就是加题顺序，拖拽要另做一套顺序维护 |
| 化学式写法归一 | 只做全角半角、空格、大小写。下标和电荷不归一，"H₂O"和"H2O"判为不同 |
| 随机抽题组卷 | 老师按自己的判断挑题。按知识点随机抽是另一套选题引擎 |
| 题目修订版 | 已通过的题不能改，要改只能新建一道，两道题在题库里并存。做修订版要维护版本链 |
| 带图的题 | 题干只收纯文本，装置图和结构式放不进来。存图要处理上传、存储、题干里怎么指位置 |
| 撤回与作废 | 发错班只能再发一份正确的，已发的记录不动 |
| 批量导入导出 | 题目一道一道录。导入要处理表格格式、题型映射、答案清洗，是另做一套解析器 |
| 删除卷子 | 这一版没有删卷入口。草稿卷留着不影响任何人，删已发布的卷要连带处理作答记录 |
